# 黄金样本·范围 B 录制备料（issue #156 阶段一）

这张票分两阶段：**现在库里只有备料**（本目录的 `macro.txt` 与本 README），
六个样本文件由人按下文录制、交回后在阶段二入库（`golden/<名>.log` +
`<名>.meta.json`，头注契约见文末）。

录制全程只在 Emuera 侧（原作游戏）操作，不碰 EraElectron。

## 一次性准备（五分钟，只做一遍）

1. **调试模式快捷方式**：给 `target/ERA魔王 年度版（名字暂定）（PC only）.exe`
   建快捷方式，右键属性，在「目标」末尾追加 ` -Debug`（注意前面有个空格）。
   之后一律用这个快捷方式启动。
2. **抬高日志容量**：完全关闭游戏后，用文本编辑器打开 `target/emuera.config`，
   把第 18 行 `履歴ログの行数:5000` 改成 `履歴ログの行数:50000`，保存
   （保持文件原有编码与换行）。#109 已实测 Emuera 接受 50000，不必分段录。
3. **拷宏文件**：把仓库里的 `golden/macro.txt` 复制到 `target/`（游戏目录）
   根下。它必须落在游戏目录才生效；**用完要删，且它不进 git**。
4. **交回文件夹**：在桌面新建文件夹 `golden-dump`，六份日志全部存这里。
5. 记下录制前 `target/Sav/` 的文件清单（当前应为 `global.sav`、`save00.sav`、
   `save99.sav`）——录制结束清场时用来对账（见文末）。

## 三条会毁掉样本的坑（#109 裁定时查实，别重试）

1. **绝不用 `@OUTPUT` 落盘**。它固定写 `target/emuera.log`——那是现有黄金
   样本且在 git 里，一敲就把比对基准覆盖掉。落盘一律用菜单
   **文件 → ログを保存する**（另存新文件名）。
2. **置位绝不走 `@` 命令**。`emuera.config:6` 打开的旧式 `@` 命令带作弊
   威慑：执行除 `@REBOOT`/`@OUTPUT`/`@EXIT`/`@CONFIG`/`@DEBUG` 外的任何
   普通 ERB 命令，MASTER 的名字与称呼会被强制改成「イカサマ」，样本里每处
   主角名都变成假差异。**置位只走 `-Debug` + Ctrl+D 调试窗口的控制台标签页**
   （无需 `@` 前缀、不改名，配置项即使为 NO 也有效）。
3. **`macro.txt` 不进 git、不留在 `target/`**。库内放本目录，用时拷入、
   用完删；不给 `.gitignore` 加豁免。

## 宏键表（`golden/macro.txt` 的全部内容）

| 键  | 宏内容（逐字，含反斜杠转义）                                 | 跑哪段                                                                                            |
| --- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| F1  | `0\n99\n`                                                    | 标题 → [0]旧的奴隶 → 读档画面 → 选 99 → 读入 → 据点主菜单。**每段录制都从 F1 开始**（它是入场券） |
| F2  | `200\n5\n\e200\n200\n对拍样本\n\e5\n1\n\e300\n102\n101\n5\n` | 存读档界面：保存(新槽) → 命名 → 保存(覆盖确认) → 读取(翻页往返) → 读入                            |
| F3  | `199\n199\n`                                                 | 日循环：休息 ×2 = 推进一日回主菜单                                                                |

语法只有三个记号：`\e`＝Esc（跳过等待中的输出）、`\n`＝提交一次输入、
`(...)*n`＝重复（本表未用到）。**宏执行中按 Esc 立即中止**——中止后按
下文各段的「失败处理」重跑即可。

> `macro.txt` 本体不带注释行：Emuera 对该文件未知行的容忍度没有查实，
> 不拿录制去赌。F 键与段的对应关系以本表为准。

**若按 F 键毫无反应**（标题画面输入框不出现 `0`）：多半是宏文件没被读到
（编码或换行不容忍）。自救：在游戏主输入框里**逐字输入** F1 的宏文本
（`0\n99\n`，反斜杠照打），然后按 **Shift+F1**——游戏会把当前输入行存成
F1 宏（顺带用它自己的格式重写 `macro.txt`）。F2/F3 同理（Shift+F2 /
Shift+F3）。存完照常按 F 键跑。

## 置位串清单（只录「最大态」的三次用；自然态什么都不粘）

用法：F1 跑完、停在据点主菜单后，Ctrl+D 打开调试窗口 → **控制台**标签页
→ 逐行粘贴下面 7 行（每行回车一次，共 7 次）：

```
FLAG:37 = 1
FLAG:83 = 5
FLAG:84 = 3
TALENT:0:325 = 1
CFLAG:(TARGET > 0 ? TARGET # 1):0 = 1
ITEM:24 = 3
ITEM:25 = 2
```

每行点亮什么（依据 `DRAW_MAINMENU.ERB` 与 `SHOP.ERB` 的渲染条件）：

| 置位                                    | 点亮                                                                                                                                                      |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FLAG:37 = 1`                           | [108] 换装（条件 `A > 0 && FLAG:37 == 1`）                                                                                                                |
| `FLAG:83 = 5`                           | [111] 设施·设备（条件 `FLAG:83 \|\| FLAG:84`）；只影响按钮与地城概况显示，**不会**触发日循环的肉便器事件（那按角色素质 `TALENT:肉便器` 判定，本次不置位） |
| `FLAG:84 = 3`                           | 同上（展品计数）                                                                                                                                          |
| `TALENT:0:325 = 1`                      | [110] 实验室（条件 `TALENT:0:325 == 1`）＋ 物品面板「所持知识」多出【魔界知识】                                                                           |
| `CFLAG:(TARGET > 0 ? TARGET # 1):0 = 1` | [106] 贩卖奴隶（条件 `B > 0`，B 统计 `CFLAG:角色:0 > 0`）；TARGET 非正时回落 1 号角色，防越界报错                                                         |
| `ITEM:24 = 3`、`ITEM:25 = 2`            | 物品面板显示 避孕套(3)、润滑液(2)（编号出自 `SHOP.ERB` @AUTO_BUYING 的注释）                                                                              |

**刻意不置位的**：`MONEY`（日循环有 `@DEBUG_CHECK` 反作弊：`MONEY !=
EX_FLAG:4444 + 8766` 触发「哥布林炸宝库」剧情并清零资金，会毁掉日循环段
的确定性）、助手相关（需要有效角色索引，save99 的实际阵容未勘明，置位
有越界与串号风险——[497] 助手按钮保持自然态，接受）。

## 六次录制（每段两份：自然态 + 最大点亮态）

通用节奏——**每段都从干净状态开始**：

> 再起動（菜单【ファイル】→【再起動】，或关掉重开快捷方式）
> → 等标题画面 → 按 F1 → [仅最大态：粘置位串 7 行] → 按该段的 F 键
> → 对照下表判定 → 菜单【ファイル】→【ログを保存する】
> → 存进桌面的 `golden-dump`，文件名按段命名 → 再起動进下一段。

顺序建议（自然态三段在前，最大态三段在后，减少来回切状态）：

1. **mainmenu-natural**：再起動 → F1 → 判定 → 存 `mainmenu-natural.log`
2. **saveload-natural**：再起動 → F1 → F2 → 判定 → 存 `saveload-natural.log`
3. **daycycle-natural**：再起動 → F1 → F3 → 判定 → 存 `daycycle-natural.log`
4. **mainmenu-max**：再起動 → F1 → 粘置位串 → **输入 `9999` 回车**
   （无效输入，主菜单原样重画——置位点亮的效果这时才显示）→ 判定
   → 存 `mainmenu-max.log`
5. **saveload-max**：再起動 → F1 → 粘置位串 → F2 → 判定
   → 存 `saveload-max.log`
   （**开跑前**确认 `target/Sav/` 里没有 `save05.sav`——有则删掉，否则 F2
   第一次保存会撞覆盖确认、宏失步）
6. **daycycle-max**：再起動 → F1 → 粘置位串 → F3 → 判定
   → 存 `daycycle-max.log`

失败处理：哪段判定不过，单独重跑那一段（再起動 → F1 → …）即可，互不影响。

## 异常态的录制结论（`(FILE LOST)` 与 `UNNAMED SAVE FILE`）

工单问这两种引擎异常态「置位造得出就一并录」。**查实：造不出，也不必造。**
依据：这两个字符串在整个 `target/` 的 ERB 与 CSV 里零出现（本票全库检索）；
本作存读档是自绘 UI（`SYSTEM_DATA.ERB`），对 CHKDATA 失败的槽位一律自画
`[ NN] ----` 灰条，永远轮不到引擎的错误串出场。因此异常态的录制点就是上表
已覆盖的：`----` 空槽、覆盖确认、三色列表项（白/绿/蓝）。**万一**录制中
真的看到这两个字符串（意味着上述判断有误），照录并在交回时注明出现位置。

## 头注契约（阶段二入库时随每份样本落 `<名>.meta.json`）

`cli.js --sample` 会机械执行这份契约：四个必填字段缺一即拒收（#156：
「置位串不落库，样本就不可重录」）。

```json
{
  "sample": "mainmenu-natural",
  "segment": "标题→主菜单",
  "state": "natural",
  "build": "93106",
  "save": "save99（第 7 日午前）",
  "seed_string": "",
  "macro_key": "F1",
  "recorded_at": "2026-01-01",
  "history_lines": 50000
}
```

- `build`：录制时 GameBase バージョン（本次固定 `93106`；标题画面的
  `伪Ver93.106` 就是它派生的自检）。旧样本 `target/emuera.log` 录自更早
  的构建且无头注（勘误二），缺省路径不查头注。
- `seed_string`：完整调试置位串，**逐行原样**（自然态为空串）。
- `macro_key`：该段内容自身用的宏键（F2/F3 段填 F2/F3；每段都以 F1 入场
  这一点不用重复记录）。
- 其余字段（`segment`/`state`/`recorded_at`/`history_lines`）为档案信息，
  不参与强制校验。
