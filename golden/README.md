# 黄金样本·范围 B 录制备料（issue #156）

**样本已入库（阶段二，#161）；本 README 保留录制方法供重录。**
`golden/` 现有六份 `.log`（mainmenu / saveload / daycycle 各 natural /
max）与同名 `.meta.json` 头注，样本名 → 文件登记表在
`tools/compare/samples.js`。第一批的宏路线（`macro.txt`）实测失败已作废
并删除；下文是第二批**已由人跑通验证的手工录制路线**，重录时照抄即可
复现同一份样本。

录制全程只在 Emuera 侧（原作游戏）操作，不碰 EraElectron。

## 一次性准备（五分钟，只做一遍）

1. **调试模式快捷方式**：给 `target/ERA魔王 年度版（名字暂定）（PC only）.exe`
   建快捷方式，右键属性，在「目标」末尾追加 ` -Debug`（注意前面有个空格）。
   之后一律用这个快捷方式启动。**快捷方式放桌面，不要放 `target/` 里**
   ——那会把脏文件带进只读输入目录、弄脏工作区。
2. **抬高日志容量**：完全关闭游戏后，用文本编辑器打开 `target/emuera.config`，
   把第 18 行 `履歴ログの行数:5000` 改成 `履歴ログの行数:50000`，保存
   （保持文件原有编码与换行）。Emuera 实测接受 50000，不必分段录。
3. **关闭自动存档**：同一文件第 8 行 `オートセーブを行なう:YES` 改 `NO`。
   该配置项的语义是「**BEGIN SHOP 时自动存档**」
   （`.agents/skills/emuera-basic-agent-guide/references/game-config/config.md:24`），
   不只在日变更时。本作未定义 `@SYSTEM_AUTOSAVE`，Emuera 走默认行为、
   **全程静默无输出**——所以关掉它对日志逐字无影响。不关的后果两条：
   `target/Sav/save99.sav`（git 跟踪的只读输入）被覆盖成第 8 日状态；
   同一段样本内 `[99]` 行会中途变化、样本失去确定性。这也是头注必填
   字段 `autosave` 的依据（见文末头注契约）。
4. **交回文件夹**：在桌面新建文件夹 `golden-dump`，六份日志全部存这里。

另外记下录制前 `target/Sav/` 的文件清单（当前应为 `global.sav`、
`save00.sav`、`save99.sav`）——录制结束清场时用来对账（见文末）。

## 两条会毁掉样本的坑（#109 裁定时查实，别重试）

1. **绝不用 `@OUTPUT` 落盘**。它固定写 `target/emuera.log`——那是现有黄金
   样本且在 git 里，一敲就把比对基准覆盖掉。落盘一律用菜单
   **文件 → ログを保存する**（另存新文件名）。
2. **置位绝不走 `@` 命令**。`emuera.config:6` 打开的旧式 `@` 命令带作弊
   威慑：执行除 `@REBOOT`/`@OUTPUT`/`@EXIT`/`@CONFIG`/`@DEBUG` 外的任何
   普通 ERB 命令，MASTER 的名字与称呼会被强制改成「イカサマ」，样本里每处
   主角名都变成假差异。**置位只走 `-Debug` + Ctrl+D 调试窗口的控制台标签页**
   （无需 `@` 前缀、不改名，配置项即使为 NO 也有效）。

## 入场（三段共用）

启动（-Debug 快捷方式）→ 标题 → 按 `0` → 读档画面 → 按 `99` →
`兼容性修正中……` → 主菜单（`第0年　1月7日（第7日） 上午　(所持金：800 pts.)`）。

注意：标题的 `0` 与读档的 `99` 等数字输入的回显行会被原作 CLEARLINE
清掉，**不会出现在日志里**——这是正常现象，不是漏录。

## 置位串清单（只录「最大态」的三次用；自然态什么都不粘）

用法：入场停下后（主菜单），Ctrl+D 打开调试窗口 → **控制台**标签页
→ 逐行粘贴下面 7 行（每行回车一次，共 7 次）：

```
FLAG:37 = 1
FLAG:83 = 5
FLAG:84 = 3
TALENT:0:325 = 1
CFLAG:(TARGET > 0 ? TARGET # 1):0 = 1
ITEM:24 = 3
ITEM:25 = 2
```

每行点亮什么（依据 `DRAW_MAINMENU.ERB` 与 `SHOP.ERB` 的渲染条件）：

| 置位                                    | 点亮                                                                                                                                                      |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FLAG:37 = 1`                           | [108] 换装（条件 `A > 0 && FLAG:37 == 1`）                                                                                                                |
| `FLAG:83 = 5`                           | [111] 设施·设备（条件 `FLAG:83 \|\| FLAG:84`）；只影响按钮与地城概况显示，**不会**触发日循环的肉便器事件（那按角色素质 `TALENT:肉便器` 判定，本次不置位） |
| `FLAG:84 = 3`                           | 同上（展品计数）                                                                                                                                          |
| `TALENT:0:325 = 1`                      | [110] 实验室（条件 `TALENT:0:325 == 1`）＋ 物品面板「所持知识」多出【魔界知识】                                                                           |
| `CFLAG:(TARGET > 0 ? TARGET # 1):0 = 1` | [106] 贩卖奴隶（条件 `B > 0`，B 统计 `CFLAG:角色:0 > 0`）；TARGET 非正时回落 1 号角色，防越界报错                                                         |
| `ITEM:24 = 3`、`ITEM:25 = 2`            | 物品面板显示 安全套(3)、润滑液(2)（编号出自 `SHOP.ERB` @AUTO_BUYING 的注释）                                                                              |

**刻意不置位的**：`MONEY`（日循环有 `@DEBUG_CHECK` 反作弊：`MONEY !=
EX_FLAG:4444 + 8766` 触发「哥布林炸宝库」剧情并清零资金，会毁掉日循环段
的确定性）、助手相关的（需要有效角色索引，save99 的实际阵容未勘明，置位
有越界与串号风险——[497] 助手按钮保持自然态，接受）。

## 三段流程（全部手工按键，已跑通；「回车」指按 Enter 跳过等待画面）

每段录两份（先自然态后最大态），文件名 `<段>-natural.log` /
`<段>-max.log`；顺序建议自然态三段在前、最大态三段在后（少切状态）。
每段判定通过后：菜单【ファイル】→【ログを保存する】→ 存进桌面
`golden-dump` → 按「跨段复位」完全退出，再进下一段。哪段判定不过，单独
重跑那一段即可，互不影响。

- **mainmenu**：入场即止（max 段：入场后 Ctrl+D 开调试窗口 → 控制台
  标签页逐行粘贴 7 行置位串、每行回车一次 → 关窗 → 主菜单输 `9999`
  回车触发重画——置位点亮的效果这时才显示）。
- **daycycle**：主菜单输 `199` 回车 → 出现 `你专心于内政…` → 一路回车
  推过回合结束输出（含 `売春判定…` 与整屏全角数字地图——那是
  `@EVENTTURNEND` 里 `SIF FLAG:502 == 1 → CALL GEO_OUTPUT_2` 的**输出**
  （SYSTEM ver1.0.3.ERB:745-746），不是交互画面，别等它）→ 回主菜单 →
  再 `199` → 同样推 → 停在 `（第8日） 上午`。
- **saveload**：主菜单 `200`（自检：标题须为「当前故事还没有名字」）→
  `200`（此处 200 = 为故事命名）→ 输 `对拍样本` → **按回车**（第一批宏
  正是漏了这一次等待才整体错位一格、把档存进了 1 号槽）→ 回保存画面 →
  `5` → `已将游戏保存为5号存档……` → **按回车** → 自动回主菜单 → `200` →
  `5` → `确定要覆盖么？` → `1` → 回车 → 再次出现
  `已将游戏保存为5号存档……` → 回车 → 回主菜单 → `300` → `102`
  （下一页）→ `101`（上一页）→ `5` → 读入 → 回主菜单。注意翻页（102/101）
  的回显与第二页列表会被原作就地清行，日志里只留最后一版第一页列表
  ——正常。

## 跨段复位（段与段之间，必须）

段与段之间**完全退出 Emuera 进程**（不是菜单的「再起動」，也不是
「回标题」）。saveload 段之后必须删 `target\Sav\save05.sav`——故事名
存在 `CSTR:MASTER:99`（`target/ERB/SYSTEM/SYSTEM_DATA.ERB:104`），
**随存档走**，只重启进程不删档清不掉，下一段的「当前故事还没有名字」
自检会失败。

## 异常态的录制结论（`(FILE LOST)` 与 `UNNAMED SAVE FILE`）

工单问这两种引擎异常态「置位造得出就一并录」。**查实：造不出，也不必造。**
依据：这两个字符串在整个 `target/` 的 ERB 与 CSV 里零出现（本票全库检索）；
本作存读档是自绘 UI（`SYSTEM_DATA.ERB`），对 CHKDATA 失败的槽位一律自画
`[ NN] ----` 灰条，永远轮不到引擎的错误串出场。因此异常态的录制点就是上表
已覆盖的：`----` 空槽、覆盖确认、三色列表项（白/绿/蓝）。**万一**录制中
真的看到这两个字符串（意味着上述判断有误），照录并在交回时注明出现位置。

## 头注契约（随每份样本落 `<名>.meta.json`）

`cli.js --sample` 会机械执行这份契约：五个必填字段缺一即拒收（#156：
「置位串不落库，样本就不可重录」；#161 补 `autosave`——自动存档状态
不落库，将来重录会得到不同的 `[99]` 行而查不出原因）。示例为库内
mainmenu-natural 的真实值：

```json
{
  "sample": "mainmenu-natural",
  "segment": "标题→读档→据点主菜单",
  "state": "natural",
  "build": "93106",
  "save": "save99（第 7 日午前）",
  "seed_string": "",
  "macro_key": "manual",
  "autosave": false,
  "recorded_at": "2026-08-26",
  "history_lines": 50000
}
```

- `build`：录制时 GameBase バージョン（本次固定 `93106`；标题画面的
  `伪Ver93.106` 就是它派生的自检）。旧样本 `target/emuera.log` 录自更早
  的构建且无头注（勘误二），缺省路径不查头注。
- `seed_string`：完整调试置位串，**逐行原样**（自然态为空串）。
- `macro_key`：第二批起恒为 `manual`——宏路线已作废（第一批六段废四段），
  字段保留是因为 cli 必填校验仍要求它存在，语义＝驱动方式。
- `autosave`：录制时「オートセーブを行なう」的开关状态，必填。本批恒为
  `false`（关）——为什么必须关、不关的后果见「一次性准备」第 3 步。
- 其余字段（`segment`/`state`/`recorded_at`/`history_lines`）为档案信息，
  不参与强制校验。

必填字段五个：`build` / `save` / `seed_string` / `macro_key` / `autosave`。
