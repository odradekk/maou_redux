# 黄金样本·出售段录制备料（issue #334）

给 `售卻相關/SELL_MATURO.ERB` 的 `@SELL_MATURO_K0`（2,071 行单函数）录一段黄金样本。
一段、一态，样本名 `sale-natural`。裁定见 #329 裁定 7。

**为什么值得录**：它是阶段 5 等待方最多的函数——15 个已完成的角色口上都在
`STUBBED_CALLS` 里挂着它，实现错了会连累那 15 份。夹具只能证明调用发生过，
证明不了演出对不对。

## 先做这两件事（`README-train.md` 说「已就绪」，那句已过期）

`target/emuera.config` 现在是导入时的原始状态（`git status` 干净，最后一次改动
是导入提交 `0b61c66`），录制前必须改回来：

| 行                             | 现在   | 改成        |
| ------------------------------ | ------ | ----------- |
| 第 8 行 `オートセーブを行なう` | `YES`  | **`NO`**    |
| 第 18 行 `履歴ログの行数`      | `5000` | **`50000`** |

自动存档不关会往 99 号槽写东西，**那正是本段的起点档**；日志容量不抬则长段会被截断。
这两处改完**保留在工作区，不要提交**（清场那一步会确认只剩它们）。

其余一次性准备沿用 `golden/README.md`：桌面 `-Debug` 快捷方式、桌面 `golden-dump`
交回文件夹。录制前 `target/Sav/` 应为 `global.sav`、`save00.sav`、`save99.sav` 三件。

## 三条会毁掉样本的坑

1. **绝不用 `@OUTPUT` 落盘。** 它固定写 `target/emuera.log`，一敲就把旧样本覆盖掉。
   落盘一律走菜单【ファイル】→【ログを保存する】另存。
2. **置位绝不走 `@` 命令**（作弊威慑会把 MASTER 改名「イカサマ」）。置位只走
   Ctrl+D 调试窗口的控制台标签页。
3. **全程不存档。** `[200] 保存` 一次都不碰。起点档 `save99.sav` 是 git 跟踪的
   只读输入。本段会 `DELCHARA` 删掉一个角色，存下去就毁了基准。

## 这一段为什么这么录（写给下一个人）

### 一、口上是必经中转，不是另一条路

主菜单不直接调 `SELL_MATURO_K0`。链条是：

```
[106] → @CHARA_SALE（选人）→ @SALE_CHARA（确认）
      → SELL_CHARA.ERB:430  TFLAG:13 = 6
      → SELL_CHARA.ERB:431  CALL SELF_KOJO
      → EVENT_K.ERB:225 @SELF_KOJO → TRYCALLFORM SELF_KOJO_K{n}
      → 口上文件的 IF TFLAG:13 == 6 块 → CALL SELL_MATURO_K0
```

全库 16 处引用（15 个口上文件 + 定义处），**没有一处来自主菜单或 `SELL_CHARA.ERB` 直调**。

### 二、`RAND` 只在一个分支里，避开它样本就能逐字比对

`SELL_MATURO.ERB` 全文 5 处 `RAND`（`:89` `:131` `:143` `:246` `:258`，注意 `:89`
是小写 `rand`），**全部落在 `:84` 的 `IF MARK:3 == 3`（反抗刻印 LV3）块内**，
且全是 `RAND:2` 只切文本分支、不参与任何数值。

另外三个顶层分支——爱慕（`:304`）、淫乱（`:932`）、其他（`ELSE`，`:1603`）——
共 1,782 行、619 个 `PRINTFORMW`，**一处 `RAND` 都没有，输出逐字确定**。

**所以录制角色必须 `MARK:3 != 3`。** 这是本段能不能逐字比对的唯一前提。

### 三、全函数只有一次输入

`:52` 的市场菜单是唯一的 `INPUT`；`WAIT`/`PRINTW`/`TWAIT` 全文 0 处，其余全是
`PRINTFORMW`（每处等一次按键）。单次运行走一条路径，约 **7–8 次回车**。

### 四、不必真的调教到可售

`@CHECK_SELLASSIABLE` 只在两处跑：每回合结束（`EVENT_TURNEND.ERB:16`），
以及**退出能力值提升界面时**（`SHOP_2.ERB:246-250`，输入 `999` 那一支）。
后者不用等一天。配合 Ctrl+D 直接置 ABL，把 5–15 个游戏日的调教压成三行置位——
`train-upgrade` 用的就是这个办法（`seed_string: "ABL:0:12 = 3"`）。

### 五、起点档的角色是随机生成的，性格要现场看

`save99` 的调教目标是**温妮**，她不在任何 `target/CSV/Chara/*.csv` 里，是随机
生成的奴隶，性格未知。而且既有样本 `golden/mainmenu-natural.log:83` 上 106 那格
是 `[---] 　　　　`——**贩卖奴隶按钮当前不显示**，因为她还不可售（`CFLAG:0 < 1`）。

性格决定走哪个口上，而**不是每个口上都调 `SELL_MATURO_K0`**：

| 结果             | 素质号                                                                                                                                       |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **会调**（可用） | 160 慈爱、161 自信家、162 懦弱、163 高贵、164 冷静、166 恶女、167 金红桃、168 银黑桃、169 黑方片、170 白梅花、172 智慧、173 庇护者、175 伶俐 |
| **不调**（要换） | 165 村娘A（K5）、171 村娘B（K11）、174 贵公子（K14）                                                                                         |

分派逻辑是 `EVENT_K.ERB:139-143`：

```
FOR COUNT,160,180
	SIF TALENT:ARG:COUNT
		LOCAL = COUNT - 60
NEXT
```

**取最后一个命中**（号最大的那个），前面那串 `ELSEIF` 已被作者整段注释掉。
所以想强制某个性格，光置位它不够，还要把号更大的全清掉——这也是为什么下面的
流程优先用她**已有**的性格，只在落进「要换」那三档时才动手。

## 录制序列

### 第 1 步：看清角色状态（不落进样本，看完继续）

主菜单 `[101] 能力显示` → 选温妮。记下三件事：

1. **性格**（对照上表）；
2. **反抗刻印的等级**——必须**不是 LV3**；
3. **是不是男性**（`TALENT:122`）——男性会被 `SIF TALENT:122 != 1` 跳过，整段不出。

看完退回主菜单。

### 第 2 步：Ctrl+D 控制台置位

打开调试窗口的**控制台**标签页，逐行敲：

```
ABL:TARGET:10 = 4
ABL:TARGET:11 = 5
ABL:TARGET:0 = 3
```

**敲完回 `[101] 能力显示` 确认三个值真的变了。** 若没变，说明 `TARGET` 在控制台里
没解析，改用她的已加入序号（`ABL:1:10 = 4` 这种形式，序号见出售名单里的 `[ N]`）。

这三个数是照 `SELL_CHARA.ERB:6-31` 的六条判定挑的，**故意避开助手判定**：

| 判定                                   | 出处     | 本组取值                 |
| -------------------------------------- | -------- | ------------------------ |
| 顺从 + 欲望 ≥ 6                        | `:12-13` | 4 + 5 = 9 ✓              |
| 阴蒂/乳房/私处/肛门 至少一项 ≥ 3       | `:15-16` | 阴蒂 3 ✓                 |
| 有【反抗心】/【刚强】则顺从 ≥ 4        | `:18-19` | 顺从 4 ✓（无论她有没有） |
| 有【克制】/【压抑】/【抵抗】则欲望 ≥ 4 | `:21-22` | 欲望 5 ✓（同上）         |
| 六选一的收尾条件                       | `:24`    | 走「欲望 ≥ 5」这一支 ✓   |
| 助手判定 `(顺从≥5 && 欲望≥4)`          | `:34`    | 顺从只有 4，**不触发**   |

最后一行是有意的：顺从取 5 会连带置 `CFLAG:0 = 2`，出售名单上就会多出
`(可做助手)` 一行（`SELL_CHARA.ERB:98`），把样本弄脏。

**只在第 1 步发现问题时才追加置位**，并逐行原样记进 `seed_string`：

- 反抗刻印是 LV3 → `MARK:TARGET:3 = 0`（否则撞上那 5 处 `RAND`，样本不可比对）；
- 性格落在「要换」三档 → 置一个可用的，**并清掉号更大的全部 160–179**。

### 第 3 步：触发可售判定

主菜单 `[105] 能力值提升` → 选温妮 → 直接输 `999` 退出。

**应当当场弹出 `温妮可以卖掉了`**（`SELL_CHARA.ERB:27`）。没弹就是置位没生效，
回第 2 步，别往下走。

### 第 4 步：出售（这一段才是样本正文）

回主菜单，**`[106] 贩卖奴隶` 这时应该出现了**（此前是 `[---]`）。

| 按         | 到哪一屏                                            |
| ---------- | --------------------------------------------------- |
| `106`      | 选人列表（`要卖掉谁呢？`）                          |
| 温妮的编号 | 评价明细 + 确认（`把温妮卖掉吗？`）                 |
| `0`        | 口上告别台词，逐屏回车                              |
| `0`        | 市场菜单选「魔界的黑市」，进 `SELL_MATURO.ERB` 正文 |

之后还会回到 `SELL_CHARA.ERB:433` 的 `温妮以{S}点卖掉了。`、威望增减、可能的
`@LONG_GOOD_BYE`（其他角色的反应），最后 `RESTART` 回选人列表。**录到回选人列表为止**，

## 逐屏对照表（全中才算录成）

### 主菜单（第 4 步起点）

### 选人列表（`@CHARA_SALE`）

| 该出现                                                                           | 出处                   |
| -------------------------------------------------------------------------------- | ---------------------- |
| `7日 午前`（`PRINTV DAY+1`＋`PRINT 日`＋`PRINTL  午前`；**不是**「第7日 上午」） | `SELL_CHARA.ERB:48-54` |
| `所持金：$800点`（`$` 是字面量：`PRINTFORML 所持金：${MONEY}点`）                | `:56`                  |
| `要卖掉谁呢？`                                                                   | `:61`                  |
| `[  N] 温妮`                                                                     | `:76`                  |
| `[评价额:____点]`                                                                | `:91`（卖价 > 0 时）   |
| `[999] - 返回`                                                                   | `:106`                 |

**不该出现** `(可做助手)`（`:98`）——出现了说明第 2 步的顺从置成了 5，重来。

### 确认屏（`@SALE_CHARA`）

先一屏评价明细（`:296-417`，逐项 `%ABLNAME%LV__ ＋____`、倍率行、`种族:`、`价钱谈判`），
然后（`:420-426`）：

```
温妮能卖出____点的样子。
把温妮卖掉吗？
 [0] - 好的
 [1] - 不要
```

`[0]`/`[1]` 前各有一个半角空格。

### 市场菜单（`SELL_MATURO.ERB:42-52`，本段唯一的输入）

```
要卖到哪个市场？
[0] 魔界的黑市
[1] 魔界的异族交易市场
[2] 魔界的宠物市场
[999] 找什么市场？随手卖掉吧！！		[1000] 水晶球记录
```

第 4 行是**一行**：`[999]` 用 `PRINT`（`:47`，末尾两个制表符）、`[1000]` 用 `PRINTL`（`:49`）。
`[1000]` 关闭时是灰色（`:48` 的 `SETCOLOR`）。

**只能按 `0`。** `1`/`2` 会跳去 `SELL_MATURO_K1`/`K2`（本票不录），
`999` 直接 `RETURN 0`、正文一行都不出，`1000` 只是翻转水晶球开关并重画。

### 正文（`SELL_MATURO.ERB` 的 ELSE 支）

结构固定：

| 段           |                                             屏数 | 出处            |
| ------------ | -----------------------------------------------: | --------------- |
| 售出对象抬头 |    4（`……买下温妮之后………` / `………` / `……` / `…`） | 如 `:2027-2030` |
| 末路正文     |                 2–7（162 个叶子里 92 个是 3 屏） | 各叶子          |
| 收尾         | 1（`就这样，%NAME:MASTER%和温妮再也没有见面……`） | `:2092-2093`    |

**预期落点**：顶层走 `:1603` 的 `ELSE`（她既无爱慕 `TALENT:85` 也无淫乱 `TALENT:76`）、
种族走 `:1843` 的非魔族、价格走「10万未満」。最后一条是推断——最低限度置位出的角色
卖价只有几千，而 `ESTIMATE_CHARA` 的加法项最大两项各 3500（`SELL_CHARA_ESTIMATE.ERB:143-144,169-170`），
凑不到 100000。**录完把实际卖价记进头注**，与这条推断对不上也不影响样本，只是落点不同。

## 头注契约（随样本落 `sale-natural.meta.json`）

五个必填字段与 `golden/README.md` 文末契约一致，缺一即拒收。示例：

```json
{
  "sample": "sale-natural",
  "segment": "据点主菜单→[106] 贩卖奴隶→选人→确认→出售口上→[0] 魔界的黑市→末路演出→回选人列表",
  "state": "natural",
  "build": "93106",
  "save": "save99（第 7 日午前）",
  "seed_string": "ABL:TARGET:10 = 4\nABL:TARGET:11 = 5\nABL:TARGET:0 = 3",
  "macro_key": "manual",
  "autosave": false,
  "recorded_at": "<录制日期>",
  "history_lines": 50000,
  "notes": "<性格、反抗刻印等级、实际卖价 S、落进哪个顶层分支与价格档>"
}
```

- `seed_string` **逐行原样**写你实际敲进控制台的每一行。追加过置位（改性格、清反抗刻印）
  的话一行不落地写上去——这份样本能不能重录，全看这个字段。
- `build` 固定 `93106`（标题画面的 `伪Ver93.106` 是派生自检）。
- `state` 取 `natural`：本段没有「点亮最大态」的对照，只录一态（#329 裁定 7）。
