# 黄金样本·调教段录制备料（issue #211 第一段）

**本文件是给 HITL 录制者的操作脚本**，形态照抄 `golden/README.md`（范围 B
三段的录制脚本，范例）。录制全程只在 Emuera 侧（原作游戏）操作，不碰
EraElectron。

本段要录**两份**：

| 样本名          | 状态                                    | 时长       |
| --------------- | --------------------------------------- | ---------- |
| `train-natural` | 纯自然态（不置位，#209 裁定 10 的那份） | 约 15 分钟 |
| `train-upgrade` | 一行置位后的升格加录（见「设计说明」）  | 约 4 分钟  |

为什么必须两份：**save99 纯自然态下一次高级 COM 升格都放不出来**，依据在
「设计说明」第 2 条；升格是这份样本相对旧样本最值钱的增量（#211 票面），
故拆一行置位的加录制出升格，置位串如实进头注 `seed_string`。若验收裁定
不加录，只交 `train-natural` 即可，其余流程一字不变。

## 一次性准备（已就绪，勿重做）

`golden/README.md` 的四项一次性准备全部沿用，**不要重做**：`-Debug`
快捷方式（桌面）、`target/emuera.config` 第 18 行日志容量 50000、第 8 行
自动存档 NO、桌面 `golden-dump` 交回文件夹。录制前 `target/Sav/` 应为
`global.sav`、`save00.sav`、`save99.sav` 三件（录完对账用）。

## 三条会毁掉样本的坑（前两条同 `golden/README.md`，别重试）

1. **绝不用 `@OUTPUT` 落盘**。它固定写 `target/emuera.log`，一敲就把现有
   黄金样本覆盖掉。落盘一律用菜单【ファイル】→【ログを保存する】另存。
2. **置位绝不走 `@` 命令**（作弊威慑会把 MASTER 改名「イカサマ」）。置位
   只走 Ctrl+D 调试窗口的控制台标签页。
3. **调教段特有：全程不存档**。主菜单的 `[200] 保存` 一次都不碰——本段
   的起点档 `save99.sav` 是 git 跟踪的只读输入，任何手动存档（尤其写进
   99 号槽）都会毁掉录制基准。调教中间态随进程退出自然丢弃，这正是我们要
   的。

## 设计说明（指令序列怎么来的；写给下一个人）

前四条是查实过的事实，逐条带出处；后三条是它们逼出来的设计。

1. **save99 的实态（渲染面证据，`golden/mainmenu-natural.log:67-77`）**：
   温妮在调教目标位、体力 1198/2000；物品栏有 振动宝石(1)、振动杖(1)、
   水晶球(1)；**`技巧Lv： Lv0`**。最后一项渲染的是 MASTER（你）的
   `ABL:12`（`DRAW_MAINMENU.ERB:335`：`PRINTFORM 技巧Lv：
Lv{ABL:MASTER:12}`）——MASTER 的技巧是 **0**。
2. **20 个高级 COM 的升格闸门逐条查过**（`COMF_JUMP.ERB` 的 `@GET_ADV_COM`
   684 行全读 + `COMABLE.ERB` 对应 `@COM_ABLE`），全部要过三道闸之一：
   MASTER 技巧 ≥ 3（84、120、121、128–134）；温妮 顺从/技巧/侍奉精神
   任一 ≥ 3（123–127）；助手在场（64、70）或 双项 ABL ≥ 3（69）。save99
   的答案是：MASTER 技巧 0；温妮在旧样本实测（第 3–4 日，
   `target/emuera.log:1685-1691`）顺从 LV0、技巧 LV1、侍奉精神 LV0，且
   点数经济极慢——第二场 28 个回合习得点数 **+0**（`emuera.log:1668`），
   32 个回合后三项 ABL 纹丝不动。**结论：自然态下零升格**，这就是拆出
   `train-upgrade` 的全部理由。
3. **升格链选 8→8→84（插入手指→插入手指→刺激Ｇ点）**，因为它是全库唯一
   「单变量闸门＋无随机＋不依赖温妮 ABL」的链：
   `SIF PREVCOM == 8 && ABL:PLAYER:12 >= 3 → RETURN 84`
   （`COMF_JUMP.ERB:140-141`）。它不调 `COM_ABLE84`（无二次筛查）、不进
   任何 `RAND` 分支。对比之下：20/21 系升格要先掷 `RAND:11` 分流 120/121；
   接吻/胸爱抚/打屁股的升格产物（128/129/132）还要过「MASTER 技巧 ≥ 3
   **或** 温妮性交技术 ≥ 2」的复核闸（`COMABLE.ERB:4159`、`4409`）；口交
   族（123–127）要温妮三项 ABL 任一 ≥ 3（`COMABLE.ERB:4008` 等）。置位
   `ABL:0:12 = 3` 之后，84 链是唯一确定生效的。
4. **实行值拒否机制**：部分指令（旧样本实测阈值：接吻 15、自慰 33、手淫
   14）在低恭顺时被拒——拒否回合只出一行
   `抖M气质LV3(6) - 反抗刻印LV1(4) + … = N < 实行值M` 判定行
   （`emuera.log:644`），无情景、无算式，且 **PREVCOM 不更新**
   （`emuera.log:640→673`：拒否后「上次的调教指令」仍是上一条真执行过的
   指令）。这就是升格链第一棒必须**真的执行**的原因，也是本序列把「必中
   指令」与「探针指令」分开标注的原因。
5. **指令方格是引擎原生育制的**，按 `Train.csv` 的 COM 号编号。现行构建
   与旧样本的编号差异（打屁股 39→40、放置PLAY 54→55、交谈 55→56、穿脱
   衣服 89→110）是已登记的 version 漂移族，**新样本照录现行编号即为准**，
   对拍层已归因，不要照旧样本的编号按。
6. **随机源不是障碍**：固定不了 Emuera 的 RNG，但不需要固定——回放层
   `tools/compare/replay.js:35` 的 `RAND_FIX` 会把 ere 侧钉到样本实际走的
   那一支（#209 裁定 12，推翻 #168 裁定 9 在本阶段的适用）。录制者对 K3
   口上的随机台词支**照录**，不要读档重试去「控制」它。
7. **序列从 save99 实际阵容出发，不照 `Train.csv` 全表排**：自然态无助手
   （助手族 60–79 整族不可选）、MASTER 技巧 0（插入族升格死）、温妮低
   恭顺（奉仕族大概率被实行值拦）。16 条指令里 11 条是旧样本里真正执行
   过的家族（爱抚/振动杖/振动宝石/穿脱），5 条是探针——探针两种结果都算
   录成，见对照表。

`train-natural.log` 进桌面 `golden-dump`。

## train-upgrade 升格加录（一行置位，约 4 分钟）

**先完全退出进程**（跨段复位），再 `-Debug` 启动 → 入场同上到主菜单。
然后：

1. Ctrl+D 开调试窗口 → **控制台**标签页 → 粘贴下面一行、回车一次：

   ```
   ABL:0:12 = 3
   ```

   （含义：MASTER（0 号角色）的 ABL:12 技巧 ← 3。语法先例同
   `golden/README.md` 置位串的 `TALENT:0:325 = 1`。）→ 关调试窗。

2. 主菜单输 `9999` 回车触发重画 → **自检：物品/技能面板必须显示
   `技巧Lv： Lv3`**。仍是 Lv0 说明置位没生效（多半没在控制台标签页），
   重做第 1 步。
3. 按 `100`（调教）→（助手选择画面若出现，按 `1002`）→ 调教画面。
4. 指令三步，**顺序不能改**：

   | 步  | 按键  | 预期                                                                                                                                                                                                                                                                                   |
   | --- | ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | a   | `8`   | 插入手指。若温妮仍是处女，先出 `夺取温妮的处女吗？ [0] - 来吧女人 [1] - 让她继续做女孩` → 按 `0`（`COMF_VAGINASEX.ERB:6-19`；已非处女则无提示）。本回合**必须出**插入手指的情景描写与算式行（`COMF8` 没有实行值闸，只有这道确认）；若整回合什么都没出，按一次 `0`（爱抚）再按 `8` 重试 |
   | b   | `8`   | 再按一次插入手指 → **升格发生**：实际执行的是 `刺激Ｇ点`（`COMF8_指挿入れ.ERB:17-20` 在 `GET_ADV_COM` 命中后 `JUMPFORM COM{RESULT}` 直跳 COM84）。判定：情景描写属于刺激Ｇ点、算式行在账、下一屏 `＜上次的调教指令：刺激Ｇ点＞`                                                        |
   | c   | `999` | 调教结束 → 结算照录 → 能力值提高阶段直接 `999` → 回车推回主菜单，停                                                                                                                                                                                                                    |

   **a →〔确认 0〕→ b 这三步是为了升格出 COM84（刺激Ｇ点），顺序不能改**；
   a 必须真的执行，b 的升格才成立（PREVCOM 机制，设计说明第 4 条）。

菜单【ファイル】→【ログを保存する】存 `train-upgrade.log` 进
`golden-dump`。

### 执行回合（每条「必中」指令都要出全）

`‥ ‥ ‥ …` 分隔行 → 情景描写行（如 `你用振动杖按压着温妮的阴部…`）→
K3 口上台词行（「哈呜、温妮…」族）→ B 文/A 文行 → 源一览行
（`阴核(300)乳房(7)…　`）→ 体力/气力损耗行（`体力[...] -5`）→ 算式行族
（`阴核  5240+   300 =  5540` 式，含 `----` 分隔与括号评语）→ 分割线 →
下一屏 `@SHOW_STATUS` 全量重绘（绝顶行、参数条变化）。

注意两处**不是错**：穿紧身衣时爱抚的情景行带「隔着紧身衣＆裙甲、」前缀，
第 3 步全裸后消失（这是两态差，正是要比对的）；口上台词是随机支之一，
照录（设计说明第 6 条）。

### 拒否回合（探针指令的可能形态之一）

指令名行（`接吻`）→ 一行判定
`抖M气质LV3(6) - 反抗刻印LV1(4) + … = N < 实行值M` → 分割线 → 下一屏。
**没有**情景、口上、源一览与算式行；`＜上次的调教指令：…＞`不因拒否变化。

### 穿脱衣服子菜单（序列第 3 步）

`现在温妮的外貌是，紧身衣＆裙甲的姿态。`（或存档实态）＋
`[1] - 紧身衣＆裙甲上半身脱掉 [2] - …的裙子脱掉 [4] - 脱掉内裤 [7] - 全部扒光 [9] - 移动到[撕破衣服] [100] - 算了`
→ 按 `7` → `温妮全裸了。` → 下一屏姿态行变 `【全裸】`，指令方格可能
多出 `胸爱抚[5]`、`乳交[32]` 等。

## 头注契约（随每份样本落 `<名>.meta.json`）

五个必填字段与 `golden/README.md` 文末契约一致（缺一即拒收）。示例：

```json
{
  "sample": "train-natural",
  "segment": "主菜单→调教 16 指令→EVENTEND 结算→回主菜单",
  "state": "natural",
  "build": "93106",
  "save": "save99（第 7 日午前）",
  "seed_string": "",
  "macro_key": "manual",
  "autosave": false,
  "recorded_at": "<录制日期>",
  "history_lines": 50000
}
```

`train-upgrade` 的差异字段：`"sample": "train-upgrade"`、
`"segment": "置位 ABL:0:12=3→插入手指×2（升格刺激Ｇ点）→结算"`、
`"state": "upgraded"`、`"seed_string": "ABL:0:12 = 3"`。

- `build`：录制时 GameBase バージョン，本次固定 `93106`（标题画面
  `伪Ver93.106` 为派生自检；旧缺省样本录自更旧构建且无头注，正是补录
  理由，`docs/output-diff.md` 勘误二）。
- `seed_string`：**逐行原样**的置位串。`train-natural` 必须为空串——录制
  中途开过调试窗口改过任何变量的话，写明改了什么，样本按不可重录处理。
- `macro_key` 恒为 `manual`；`autosave` 恒为 `false`（不关的后果见
  `golden/README.md` 一次性准备第 3 步）。
