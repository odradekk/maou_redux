# ere-example — conclusions and pitfalls

> **本文是快照**：与例程源码、引擎源码或 wiki 有出入时，以它们为准。本插件内置的 `assets/sdk/era-electron.js`
> 与引擎仓库的 `sdk/era-electron.js` 逐字节相同，可直接作为 SDK 的真值来源。

The official example game is the `example/` submodule of the engine repository
([`ere-example`](https://gitgud.io/umaera/game/ere-example), `master` only). This plugin does **not** bundle it:
the `ere-game-development` skill fetches it on demand, and **the example's own `AGENTS.md` is the file map** —
go there for "which file implements which system". This document deliberately keeps only what the source and the
file map do not state by themselves.

---

## 1. Two runtime modes, and the minimum file set

The engine's loading sequence (`src/era/model/era-start.js`, wiki `01-basic.md` §"EraElectron运行流程") defines the
minimum precisely. The minimum differs per mode.

### 1.1 Mode A — PC / raw-script mode (what `ci/build.js` ships, what a scaffold should assume)

A game folder must contain:

| # | File | Required? | Why |
|---|------|-----------|-----|
| 1 | `csv/GameBase.csv` (or `gamebase.json`/`.yml`) | **REQUIRED** | Without it the engine prints `GameBase.${suffix} 不存在! 游戏数据载入失败!` and aborts (`if (!this.staticData.gamebase)`). It must supply at least: 游戏名称, 作者, 追加信息, 发布时间, 游戏标识, 版本, 最低支持版本. |
| 2 | `ere/main.js` | **REQUIRED** | The engine requires `ere/main.js` as the script entry and expects a `module.exports = async () => {...}` function. |
| 3 | `ere/era-electron.js` (or any script loaded by `main.js` that is recognised as the SDK) | **REQUIRED** | After loading the scripts the engine looks for the loaded SDK and links every API onto it; without it the game cannot talk to the engine ("游戏脚本集下必须有一个类似era-electron.js的脚本文件"). Copy it verbatim from the engine `sdk/era-electron.js`. |
| 4 | `csv/` directory itself | **REQUIRED in practice** | The engine probes the game folder in the fixed priority order `yml` → `json` → `csv` (`staticFormatPriority = ['yml', 'json', 'csv']`), or the format named by `ere.config.json` `system.static`, and uses the first directory that exists; if none does: `静态数据文件夹 (yml / json / csv) 不存在! 游戏数据载入失败!` and abort. An empty `csv/` technically loads but the persistent tables stay undefined, so nothing works. |
| 5 | `ere/` directory itself | **REQUIRED in practice** | It is the script root and the location of `main.js`/`era-electron.js`. |

That is genuinely all. The wiki's own "新建项目" recipe is exactly this five-item skeleton, and its complete `main.js`
is:

```javascript
const era = require('#/era-electron');

module.exports = async () => {
  era.print('Hello World!');
};
```

A minimal *usable* game (not just loading) should add, in rough order of importance:

| File | Adds |
|------|------|
| `csv/Flag.csv` | At least one system variable to persist game state (`flag:*`). |
| `csv/Chara/Chara0000.csv` | A predefined protagonist so `era.addCharacter(0)` / `defaultChara` yields real data. |
| `csv/Base.csv` | `base:*`/`maxbase:*` character stats (needed by any HP-style UI). |
| `csv/Abl.csv`, `csv/Exp.csv`, `csv/Talent.csv`, `csv/CFlag.csv`, `csv/CStr.csv`, `csv/Mark.csv`, `csv/Item.csv` | The remaining character-scoped tables the example UI reads. |
| `csv/Param.csv`, `csv/Source.csv`, `csv/Ex.csv`, `csv/TFlag.csv`, `csv/TEquip.csv`, `csv/Stain.csv` | Only if the game uses the training (调教) subsystem, which calls `era.beginTrain`/`nextTurnInTrain`/`endTrain`. |
| `csv/Global.csv` | Only if save-slot metadata / cross-save globals are wanted (the example instead writes `global:saves:*` without declaring `Global.csv`). |
| `ere/jsconfig.json` | Editor path-alias support only. |

### 1.2 Mode B — Android / bundle mode (`dist/` produced by webpack)

The engine takes this branch only when **all three** files exist in the game folder:
`static.json`, `era.bundle.js`, `main.bundle.js` (`era-start.js`: `existsSync('static.json') && existsSync('era.bundle.js') && existsSync('main.bundle.js')`).
In that mode `csv/` is not read at all — the entire static dataset comes from `static.json`. So the minimal bundle is:

| # | File | Required? | Why |
|---|------|-----------|-----|
| 1 | `static.json` | **REQUIRED** | Contains `config`, `names`, `static`, `res`, `extend`, `fixed`; generated by the engine menu 「生成静态文件」 from `csv/`, or copied from `build/static.json` by `ere-webpack-plugin`. Must contain a `static.gamebase`. |
| 2 | `era.bundle.js` | **REQUIRED** | Webpack bundle of the SDK (`entry.era`), exposing `_era`. |
| 3 | `main.bundle.js` | **REQUIRED** | Webpack bundle of the game entry (`entry.main`), exposing `game`. Built from `ere/main.js`. |
| 4 | `res/` (or paths inside `static.json`) | Optional | Only if `system.resource` is true; resource paths inside a bundle are converted to `eeip://`/`emip://` local-file URLs. |

The example's webpack config produces exactly this trio (`dist/era.bundle.js`, `dist/main.bundle.js`,
`dist/static.json` written by the plugin's `afterEmit` hook), and `build/static.json` is the committed input to that
plugin. `package.json`, `webpack.config.js`, `eslint.config.js`, `.husky/`, `ci/`, `.gitlab-ci.yml`, `.ere-min-version`
and `README.md` are **developer/CI tooling only** and are never read by the engine.

### 1.3 Required vs optional, for a new project

| Path | Class | Notes |
|------|-------|-------|
| `csv/GameBase.csv`, `ere/main.js`, `ere/era-electron.js`, `csv/` | **engine-required** | Removing any of them prevents loading (or produces a scriptless game). |
| `csv/Base.csv`, `Abl.csv`, `Exp.csv`, `Param.csv`, `Talent.csv`, `Mark.csv`, `Item.csv`, `Flag.csv`, `CFlag.csv`, `CStr.csv`, `TFlag.csv`, `TEquip.csv`, `Source.csv`, `Ex.csv`, `Stain.csv` | **optional per table** | A missing table just leaves its `staticData` entry undefined; scripts that reference it then fail, so drop only tables the scripts do not use. |
| `csv/Chara/*.csv` | **optional** | No character files = no predefined characters; `csv/Chara/` may use any `Chara*.csv` basename. |
| `csv/_Replace.csv` | **optional** | Read only when `system._replace: true`. |
| `csv/_config.json`, `csv/_fixed.json` | **optional** (not present in example) | Default and forced game config; `_fixed.json` wins and locks values. |
| `ere.config.json` | **optional / generated** | Written back by the engine on every launch; git-ignored. |
| `ere/jsconfig.json` | **optional (dev)** | IDE only. |
| `ere/page/*.js`, `ere/event/**`, `ere/sys/**`, `ere/utils/**`, `ere/data/**` | **optional (game code)** | Pure game logic layered on the SDK; a minimal game needs none of them. |
| `build/static.json` | **required only for the bundle build** | Input to `ere-webpack-plugin`; absent → `Build failed: no static.json!`. |
| `webpack.config.js`, `package.json` devDependencies, `.husky/pre-commit`, `eslint.config.js` | **optional (tooling)** | Only needed to build/lint/package. |
| `ci/build.js`, `ci/android.js`, `ci/pages.js`, `.gitlab-ci.yml`, `.ere-min-version` | **optional (CI/release)** | Only for GitLab release automation and the auto-update/version-check system. `.ere-min-version` is read by `ci/build.js`/`ci/pages.js`; the Android engine compares the `RELEASE` file (or `版本检查` URL) against `GameBase` `版本`/`最低支持版本`. |
| `res/` | **optional** | Required only for images/audio. |
| `sav/`, `dist/`, `node_modules/`, `ere.config.json` | **generated/ignored** | Absent from the checkout; listed in `.gitignore`. |

### 1.4 Hard facts a scaffolder must honour

1. **Encoding**: write every script and CSV as UTF-8 (with or without BOM). The engine accepts both and strips BOMs
   via `fuckOffUtf8Bom`; the example itself uses **UTF-8 without BOM** everywhere. Excel users are advised by the wiki
   to use UTF-8-BOM so Excel does not mangle Chinese text.
2. **Static format priority**: if more than one of `yml/`, `json/`, `csv/` exists, **`yml` wins over `json` over `csv`**
   (`staticFormatPriority`), unless `ere.config.json` `system.static` names the desired one. The example ships only
   `csv/`, so it resolves by fallback. A scaffolder must not leave a stray `json/` or `yml/` directory around when it
   means to use `csv/` — except in bundle mode, where `static.json` short-circuits the whole branch.
3. **Line endings**: the example is uniformly **LF**, and nothing in the engine requires CRLF. `eslint.config.js`
   sets `endOfLine: 'auto'`, `ci/build.js`/`ci/pages.js` strip `\r`-adjacent whitespace with `.replace(/\s+$/, '')`, and
   the CSV parser splits on newlines, so both LF and CRLF work; LF is the canonical choice.
4. **The `#` alias must exist in two places** if editor tooling and the webpack build are both wanted:
   `ere/jsconfig.json` (`"paths": {"#/*": ["*"]}`) and `webpack.config.js` (`resolve.alias['#'] = resolve(__dirname, 'ere/')`).
   Without the webpack config the `#/` requires break in the bundle build; the raw PC build never resolves them (the engine
   supplies `_require`/`require` redirection when it loads scripts — see `era-start.js` `this._module.prototype.require = this._require`).
5. **`ere/era-electron.js` must be re-copied from the engine SDK** whenever the engine is upgraded. Its
   `version.sdk` must satisfy `>= 4.7.0` (the requirement `ere-webpack-plugin` enforces at build time) and
   `<=` the engine version (the engine's own runtime check).
6. **`GameBase` version consistency**: `ci/build.js` and `ci/pages.js` parse the version by searching `csv/GameBase.csv`
   for the literal prefix `版本,`; `package.json.version` and `.ere-min-version` are kept in the same `0001` format. A
   JSON/YAML static dataset requires patching those two CI scripts (the comments in `ci/pages.js` say exactly this).
7. **Event queue durability**: any queue state intended to survive save/load must live in CSV-declared tables
   (`flag:事件队列` in the example) and be re-hydrated with `init_queue()` after new-game/reset *and* after
   `era.loadData`.

## 2. The CSV dialect, measured on all 20 files

| Question | Answer |
|----------|--------|
| UTF-8 BOM present? | **No.** Every file in `csv/` (and every file in the repo) starts with its literal first character; no `EF BB BF` prefix anywhere. |
| Encoding? | **UTF-8, no BOM** for all 20 CSV files (verified by decoding each as UTF-8 successfully; `file(1)` reports "Unicode text, UTF-8 text" for all of them). |
| Line endings? | **LF (Unix `\n`) only.** Count of `\r` bytes is **0** in all 67 files. No CRLF and no lone CR anywhere. |
| Trailing newline? | **Mixed.** `GameBase.csv`, `Abl.csv`, `Base.csv`, `Ex.csv`, `Exp.csv`, `Flag.csv`, `Item.csv`, `Mark.csv`, `Param.csv`, `Source.csv`, `Stain.csv`, `Talent.csv`, `_Replace.csv` and all three `Chara/*.csv` files end **without** a trailing `\n`. `CFlag.csv`, `CStr.csv`, `TEquip.csv`, `TFlag.csv` are single-line files also without a trailing `\n`. |
| Separator | ASCII comma `,` (half-width). |
| Comments | Lines starting with `;` are comments; an inline `;` also starts one (see `Talent.csv`). Blank lines are allowed and skipped. |
| Are there header rows? | **No.** Every table is pure `key,value...` rows; the "format" of each file is its first data row pattern. |
| Case handling | The engine lower-cases file names and every non-comment value read from these files, while `era.get`/`era.set` lookups are also case-insensitive; file *references* inside scripts must match case exactly. |

Column shapes actually used by the example:

- 2 columns `id,name`: `Base`, `Abl`, `Exp`, `Param`, `Talent`, `Mark`, `Flag`, `CFlag`, `CStr`, `TFlag`, `TEquip`, `Source`, `Ex`, `Stain`.
- 3 columns `id,name,price`: `Item`.
- 2 columns `name,value`: `GameBase`, `_Replace` (no numeric ids).
- `Chara/*.csv`: 2 or 3 columns, first column is a **table/field name**, not an id (`角色编号,0`; `基础属性,体力,2000`;
  `特性,C感觉,1`; `角色Str,代表色,#ff7373`).

Tables the engine knows but the example does **not** ship: `Global.csv` (global table), `Equip.csv` (`equip`),
`TCvar.csv` (`tcvar`), `Palam.csv` (another name for `Param.csv`), plus any developer-extended tables. Their absence is
not an error: a missing table simply leaves `this.staticData[k]` undefined. Protected/deprecated table names
(`maxbase`, `delta`, `juel`, `jewel`, `gotjuel`, `nowex`, `static`, `callname`, `relation`, `res`, `str`, `globals`,
`train`, …) are skipped with a console warning if present as a file.

## 3. Code layering and conventions

```
ere/main.js                      entry point (module.exports = async function)
 ├── era-electron.js             engine SDK (declared API; engine injects real implementations)
 ├── sys/                        framework-free helpers (event queue, random-event adapter, check helpers)
 ├── utils/                      pure helpers (colour gradient, RNG)
 ├── data/                       enums + tiny classes (ero constants, event objects/hooks)
 ├── event/                      "口上" (per-character custom text) + training text
 │    ├── line-base.js           shared base class (id/name/callname)
 │    ├── lines/                 talk/switch lines + factory
 │    └── ero/                   training lines + factory + result handlers
 └── page/                       full-screen interaction loops, one file per screen
```

- Absolute requires via `#/...` (webpack alias `#` = `ere/`, mirrored by `ere/jsconfig.json`). All internal requires
  use it; only the SDK is required as `#/era-electron`.
- Every module is CommonJS (`require` / `module.exports`); ESLint enforces sorted requires.
- `era` is a **singleton object** required by every module; there is no dependency injection.
- A "factory" module keeps a `cons_dict` (per-character class registry) and an `obj_dict` (instance cache) and exposes
  `get_custom_*` + `run_custom_*(id, key, ...)` as the only entry points.
- Every "page" is an `async function` that renders with `era.print*`, awaits `era.input()`, and clears/redraws itself,
  ending by `module.exports = page_x`.
- Character-specific text ("口上") is selected by the `cflag:${id}:口上` value through `get_this()`; the generic class
  is the fallback when a character has no registered subclass.
- The event queue is persisted inside the save data under `flag:事件队列`, so queued random events survive save/load.
