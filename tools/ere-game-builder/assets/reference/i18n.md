# i18n（多语言）参考实现

一个「基底库 + 若干翻译包」的多语言方案的实际实现摘要。整理自作者提供的一个工程的多语言目录
与该工程入口的两个标题界面按钮，**不是原文件的复制**。

这里的重点有两层：**① 多语言机制本身怎么组织**；**② 它把静态数据当成了文案来源** ——
这一点决定了在别的工程里照搬它时必须先做什么。

> 该方案是一个**简单但够用**的形态：语言包在启动时全部实例化、语言清单硬编码在 selector 里。
> 更稳健的做法（懒加载、缺键回退链、复数/性别规则等）在需要时再考虑，本实现刻意不做。

## 目录结构

```
ere/i18n/
├── selector.js          # 语言选择与取词入口（唯一被全局引用的文件）
├── <语言 id>/           # 如 zh-CN、ja-JP
│   ├── entry.js         # 语言包主体：一个类，字段就是文案
│   ├── kx.js            # 口上文本的承载类（字段 = .kojo 文件对象）
│   ├── kx/
│   │   ├── str.kojo     # 长文本 / 口上（YAML，见下）
│   │   └── info.kojo
│   ├── table/<表名>.js  # 表变量名的译文（键与开发套件同名模块一致）
│   ├── chara/names.js   # 角色名
│   ├── chara/callnames.js
│   └── train.js         # 调教相关文案
```

**基底库是 `zh-CN`。** 其他语言的 `entry.js` 直接 `extends` 基底库的类并覆盖字段，只写自己需要改的键。

## 取词入口（selector.js）

```javascript
const { __, i18n, lan, lans, set_lan } = require('#/i18n/selector');

i18n().tt_new_game        // 直接取字段（IDE 可补全）
i18n('ja-JP').location    // 指定语言取
__('kx.str.opening')      // 点路径取词，取不到返回基底库的 not_found
lans()                    // ['zh-CN', 'ja-JP'] —— 语言清单
set_lan('ja-JP')          // 切换（未知语言会被静默忽略）
```

三个要点：

- **两种取词风格并存**：`i18n().字段` 走对象属性（有类型提示），`__('a.b.c')` 走点路径（适合嵌套，如口上）。
- **`lans()` 是硬编码的语言清单**（selector 里逐个 `new` 出来），加一门语言要改这一处。
- **`set_lan` 对未知语言静默无效**：传错语言 id 不会报错，只是语言没变。切换后调用方需要自己持久化（见下面的按钮）。

## 基底库 = 静态数据的投影（关键）

基底库（`zh-CN/entry.js`）**不手写表变量名的中文**，而是直接引用**开发套件**生成的表名模块：

```javascript
const { eraAblNames } = require('#/era-utils/names/era-abl-names');
// … 每张表一个

class I18nEntry {
  tb_abl = eraAblNames;     // 表变量名直接来自开发套件
  tb_base = eraBaseNames;
  tb_item = eraItemNames;
  // …
}
```

于是：

- **表名的单一事实来源是静态数据本身**（经开发套件导出），不存在"文案表与数据表不同步"的问题；
- **翻译语言只需要提供"值"**，键由开发套件决定。翻译包的 `table/<表名>.js` 就是一个键相同、值不同的对象：

```javascript
// <其他语言>/table/abl.js
module.exports = { meek: '従順', lust: '欲望', skill: '技巧', /* …与开发套件同键 */ };
```

### 表变量名的来源：先问，再定

表变量名是这套 i18n 的前置条件。**生成 i18n 之前先问用户三件事**：

1. **静态数据是什么语言**（决定基底库能不能直接用套件，见下一节）；
2. **基底库想用哪个语言**；
3. **是否使用开发套件**。

| 情况 | 做法 |
| --- | --- |
| 数据语言 **==** 基底库语言，用户**选择用套件**，且工程里**已有**套件 | 直接引用，不要重复造 |
| 同上，但工程里**没有**套件 | **请用户生成开发套件**（引擎菜单【帮助】-【生成开发套件】需要人在引擎界面操作，agent 做不到），生成后再引用 |
| 用户**不想用**套件，或数据语言 **≠** 基底库语言 | 由生成 i18n 的一方**从静态数据自行导出**「变量名 → 显示名」映射：读 `csv/`（或 `json/`、`yml/`）的变量表，写成与套件同形的模块（键 = 变量名，值 = 显示名），再让基底库引用它。引擎自己的套件生成器读的就是这些静态数据，因此两者等价 |

**为什么优先用套件**：套件是引擎按静态数据生成的**同一份数据**，引用它不产生第二份副本；而自行导出会与
套件（现在已有的，或以后补生成的）**重复占用内存**，两份还可能各自漂移。所以「用套件」是更优的工程实践，
自行导出只在用户选择不用（或语言关系不满足）时作为兜底。

### ⚠️ 前提：基底库的表名语言取决于静态数据的语言

`era*Names` 的**值就是静态数据里的显示名**（例：`{ meek: '顺从' }` —— 数据是中文，它就是中文）。
所以「基底库用开发套件当表名」**只在「静态数据语言 == 期望的基底库语言」时成立**：

| 实际情况 | 该怎么用开发套件 |
| --- | --- |
| 静态数据语言 **==** 期望的基底库语言 | 直接拿 `era*Names` 当基底库表名（本参考实现即此情形） |
| 静态数据语言 **≠** 期望的基底库语言 | **基底库必须自己提供表名译文**（`table/<表名>.js`）；套件只能当"数据语言那一层"的兜底，否则基底库会露出数据语言 |
| 工程没有套件 | 由生成 i18n 的一方从静态数据导出（见上表） |

因此**生成 i18n 前应当先问用户三件事**，而不是假定：静态数据是什么语言、基底库想用哪个语言、
工程里有没有开发套件。

## `static _`：基底库的辅助类只构造一次

`static _` **只定义在基底库（zh-CN）**的辅助类上，共 6 个：`train`、`kx`、`chara/names`、
`chara/callnames`、`table/talent-desc`、`table/stain-desc`。

```javascript
// 基底库：类定义时构造一次，供所有语言包共享
class I18nKx {
  static _ = new I18nKx();
  /** @type {KojoFile} */
  str = require('#/i18n/zh-CN/kx/str.kojo');     // .kojo 的 require 发生在字段初始化时
  info = require('#/i18n/zh-CN/kx/info.kojo');
}
module.exports = I18nKx;

// 基底库的语言包用 ._ 取那一个共享实例
kx = require('#/i18n/zh-CN/kx')._;

// 翻译库的语言包则直接实例化自己库里的类（覆盖字段必须在实例上才生效）
train = new (require('#/i18n/ja-JP/train'))();
kx = new (require('#/i18n/ja-JP/kx'))();
```

原因：selector 在启动时会把**每个**语言包都 `new` 一遍。基底库的辅助类若不做单例，语言包有几个就会
重新构造几次（并重复触发 `.kojo` 的 `require`）。所以基底库共享一份，翻译库各造自己的一份。

> **为什么 `era*Names` 不需要 `static _`**：它是开发套件生成的**普通对象**，写在模块作用域
> （`const eraAblNames = { meek: '顺从', … }; module.exports = { eraAblEnum, eraAblNames };`，文件里没有
> `class` 也没有 `static`）。Node 会缓存模块，任何语言包 `require` 同一路径拿到的都是**同一个对象**，
> `tb_abl = eraAblNames` 只是存了个引用 —— 天然就是单例。需要 `static _` 的只有那些**类**。

> **注意**：翻译库的类**不**定义 `static _`。若你给某个翻译库也加上 `static _`，又让另一个类去
> `extends` 它（例如「第三门语言继承第二门」），那么 `Sub._` 会沿构造器原型链解析到**被继承者**的
> 实例，覆盖字段不生效、且不报错。这种情况要用 `new Sub()` 取实例，不要用 `._`。

## 文案的四种形态

| 形态 | 例 | 说明 |
| --- | --- | --- |
| 字符串 | `tt_new_game = '开始游戏'` | 最常见 |
| 带占位符的字符串 | `ui_talent_span = '【%TALENT%】'` | `%KEY%` 与 `.kojo` 的 dict 替换**同一套约定** |
| 数组（与引擎数据位置对齐） | `cl_sp = ['手套', '袖子', …]`、`race = ['人类', …]` | 下标必须与引擎数据（服装槽位、种族 id 等）一致 |
| 函数（组合打印参数） | `ui_slave_full_info = (name, talent, …) => [ …this.ui_slave_info(name), `${this.tb_abl.meek} Lv.${meek}`, { isDivider: true } ]` | 返回可直接交给 `era.print*` 的参数数组；可引用 `this.tb_*` 拼表名，也可调用同类其他字段 |

字段名用**前缀**表达用途：`tt_` 标题界面 / `ng_` 开始游戏 / `hm_` 主界面 / `ed_` 结局 / `ui_` 通用界面 /
`tb_` 表变量名 / `ds_` 显示名 / `kx` 口上 / `train` 调教 / `cl_*`、`race` 引擎数据对齐数组。

## 口上文本用 `.kojo`（含接驳配方）

长文本（口上、说明）不放在 JS 里，而是放 `.kojo`：

```javascript
// kx.js：字段承载，配合 static _ 共享实例
str = require('#/i18n/zh-CN/kx/str.kojo');
info = require('#/i18n/zh-CN/kx/info.kojo');
```

```javascript
// 调用方：require 得到的是 { 篇目名: async (dict) => … }
await i18n().kx.str['opening']({
  'NAME:MASTER': i18n().ds_name[me.name] ?? me.name,
  'STR:100': i18n().location,
});
```

接驳要点：

1. `require('#/…/x.kojo')` 返回**对象**：`{ 篇目名: 异步函数 }`，篇目名就是 `.kojo` 里的顶层键；
2. 调用时传一个 **dict 对象**做 `%KEY%` 替换，键写 `%NAME:MASTER%` 这样的形式；
3. **dict 的值应当是已本地化的**（例：角色名先经 `ds_name` 取译文），否则口上会中英日混排；
4. **一般工程里把 JS 口上改成 `.kojo`**：机制（派发、钩子、状态）留在 JS，把口上类里**每个输出点**
   换成 `await lines['篇目名']()` 即可 —— 也就是"文本搬进 `.kojo`，逻辑留在 JS"；
5. 代价：文本离开 IDE 的类型检查；`.kojo` 里只能写 YAML 能表达的值（不能是函数）。

## 两个标题界面按钮

```javascript
// ① 语言 / Language：用各语言的自称显示，选中后写回引擎全局并持久化
lans().forEach((l, i) => era.printButton(i18n(l).language, i + 1));
set_lan((era_global.language = lans()[(await era.input()) - 1]));
await era.saveGlobal();

// ② Check Lan Lib：输入语言 id，递归比对基底库
if (!lans().includes(lan)) return;                  // 不存在的语言直接拒绝
if (lan === 'zh-CN') return;                        // 基底库不用检查
do_check(key_path, aim_lib, cn_lib);                // 递归遍历 zh-CN 的每个键
```

`do_check` 会报三类问题，都是**翻译漏项**的常见形态：

- `[WARN] miss:` —— 基底库有这个键，目标语言没有；
- `[WARN] miss or equal:` —— 值**与中文完全相同**，很可能漏翻；
- 类型不一致 —— 基底是函数/数组，目标语言写成了字符串之类。

语言 id 存在引擎全局 `era_global.language`（缺省 `zh-CN`），启动时 `set_lan(era_global.language ??= 'zh-CN')`
读回；切换语言后需 `era.saveGlobal()` 才会持久化。

## 加一门语言的步骤

1. 新建 `ere/i18n/<语言 id>/`；
2. 写 `entry.js`：`module.exports = class extends require('#/i18n/zh-CN/entry') { language = '<自称>'; /* 覆盖要翻译的字段 */ }`；
3. 需要翻译表变量名时，加 `table/<表名>.js`（**键与开发套件同名模块一致**，只写值）；
4. 需要翻译口上时，加 `kx.js` + `kx/*.kojo`（`kx.js` 用 `static _` 暴露单例，或直接提供 `kx` 字段）；
5. 角色名/默认称呼：`chara/names.js`、`chara/callnames.js`；
6. 在 `selector.js` 的 `dict` 里 `new` 这个语言包；
7. 进游戏用标题界面的「Check Lan Lib」按钮逐个补齐漏项。
