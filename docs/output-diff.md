## 硬边界

**调教段**：旧样本（`target/emuera.log`）只覆盖调教这一段。「比对通过」
目前只等于「调教的这一段对得上」（#9 勘误一：样本是环形缓冲尾部 5000 行，
无标题画面、商店、迷宫、日循环；勘误二：样本录自比 `target/` 更早的构建）。

**范围 B 三段两态（#161 起）**：`golden/` 的六份样本覆盖
①标题→读档→据点主菜单、②存读档界面（命名/保存/覆盖/读取）、③日循环
（休息×2 推进一日），每段 save99 自然态 + 置位最大态两份——`node
tools/compare/cli.js --sample <名>` 逐份比对（六份的基线四数锁在
`test/compare-scope-b.test.js`）。「范围 B 比对通过」= 这三段两态的
输出流对得上，其中每条差异都有名有姓（rules.js 的范围 B 规则组）。

**范围 B 之外（迷宫、战斗、口上、调教深化）明确只靠单测与实机验收**，
不做对拍（#109 裁定问题六）；移植到那些子系统时先补样本、扩归因，再谈
「比对通过」。范围 B 内也有结构性不可比项：编号复用画面的集合配对错位、
ere 引擎的按钮/清行形态差（见 rules.js 范围 B 块注释），它们归因而非
消失。

## 三个设计裁定（工单留给这张票的问题）

### 1. 比对起点：手工播种等价角色，不解析 save00.sav

依据：

- 首回合的全部初始值**可从日志自身推导**。PALAM 初值 = 算式行 from 侧
  （`阴核 5240+300=5540`）；BASE 初值 = 回合后状态条 + 损耗回推
  （(1445/2000) + `-5`）；ABL / 素质 / 刻印 / CFLAG 由源一览与换算结果反解
  （`tools/compare/replay.js` 的种子表逐条注明证据行；推导表见文末）。
  8 条算式断言在回放的 before/after 两端全过（`test/compare-first-turn.test.js`），
  是「推导自洽」的机器证明。
- `save00.sav` 与日志窗口的**时间对齐关系不可知**：日志是同场次的尾部
  5000 行，存档是同场次的某一时刻——解析它得到的不是「窗口起点」。
- 二进制格式解析是独立工作量，解析器自身的 bug 会伪装成比对噪音，
  #9 原型的静默截断缺陷就是这类。播种复用夹具既有机制，零新增采集面。

### 2. 录制器：复用 #16 夹具，不另造 print 代理

#9 原设「ere 侧包一层 print 代理、需要测试模式开关」是在夹具（#16）之前
定的。夹具已经是那个代理：加载真实 SDK、就地替换函数、游戏代码零修改。
再造第二个录制器会有两份「游戏输出了什么」的真相源。这张票对夹具的唯一
改动是**补齐 print 系覆盖**（printMultiColumns / printInColRows / printImage
的逐格记录，加法式、全部既有测试不受影响）；输入标记由回放器在夹具之外
包装 `era.input` 压入 lines（输入不是输出，不属于夹具的职责）。

### 3. LCS 粒度与装饰行的判定

- **粒度**：一「格」一条目。菜单行拆成 (标签, 编号) 条目、参数条网格拆成
  (键, 数值) 条目、算式行拆成数值四元组；text / input / calc / lossbar 走
  LCS（叙事次序是行为的一部分），menu / gauge 走集合比对（画面布局无次序
  语义，集合化就是「容忍排版差异」的实现；检验 2 重跑通过）。
- **装饰行**：空行 / 分割线 / 省略号整体丢弃。本分类器实测 5000 行样本：
  空行 260 + 分割线 462 + 省略号 364 = 1086 行（**21.7%**；#9 原先统计为 21.2%，
  差额是本分类器把 palam_up 的 31 字符短分隔线也计入 divider）。量级与
  结论不变：比对它们只产生噪音。

## 增补裁定：结构化进度条记录 → gauge（#74，让表现层可替换而不破坏比对）

ere 侧的 gauge 来源自此分两路：

- **文本记录仍走 `classify_line`**（与黄金样本同一套分类器）。它不能随
  #74 删除：损耗条（`体力[...] -5` 行）仍由 SOURCE_CHECK 以合成串产出，
  它归调教循环那边管（#74 边界外）。等损耗条的票把它也结构化，ere
  路径的网格解析才能退役。菜单侧自 #48 起就走 button 记录，与文本路径无关。
- **progress 记录（printProgress / printMultiColumns 的 progress 格）零
  解析直映射**：

  ```js
  { kind: 'gauge', key: 条内文字 /* 参数名 */, val: Number(条后数值) }
  ```

  键与值来自参数，右对齐填充由 `Number` 剥掉（outContent 为空串时归一成
  val=0 而非 NaN。值与黄金侧不符照样红，M12 变异证明比对能拦下）。

**percentage 永不进事件流。** 它属于渲染层的算法（原作 10 格字符条
`floor(10×值/下一阈值)` vs 引擎百分比条的取整差异），两侧归一的语义值是
**条后数值**（palam 原值）。`print_palam` 换 printMultiColumns 的 progress
格（#74）后，事件流与手绘合成串时代逐字节同构：首回合比对的基线
（匹配 54 / 版本 10 + 存根 112 + 未解释 0）不动，这正是「换掉表现层不影响
比对」的机器证明。ere 侧手绘合成串的**产出端**就此消失（一整类 ere 侧 gauge
正则误判随产出端消失），黄金样本侧的解析原样保留（Emuera 只有合成串）。

归一化器变异自证：M148（val 误读 percentage）/ M149（progress 分支删除）
均由 `test/compare-normalize.test.js` 与首回合比对拦下。

## 范围 B 的三处裁定（#161 阶段二，判断依据 = 六份真样本）

### 1. 归一化器：七类条目够用，扩展的是「哪些行进哪类」

主菜单/存读档/日循环的实际形态（`golden/` 样本实证）与调教段的差异不在
条目类型，在解析形态——**不新增条目类型**，扩展三处（normalize.js）：

- **编号在前的按钮/槽位行**：`[100] 调教`、`[101] 上一页 …`、`[ 5] 备注`
  拆成 menu 条目（调教段 SHOW_USERCOM 的「标签在前」是仅有的例外，其余
  UI 全是编号在前）；`[---]` 灰条单元归 text 残段（ere 侧灰条正是
  `era.print('[---]')`，两侧同构）。整行必须由 `[单元] 标签` 铺满，有
  残渣即整行回落 text——叙述文本里的编号引用不被误拆。
- **时间戳归一（验收项）**：存档备注的 `YYYY/MM/DD HH:MM:SS` 前缀替换成
  `<TS>` 占位，黄金侧标签段与 ere 侧 button 正文同一条规则。**归一而非
  忽略**：时间戳的存在与格式仍是断言（丢了照样红），只有值不比——重录
  时刻必然不同，比值必假红。
- **富文本标记行**：`<shape …><img src='X' …>` 抠出 img src → image 条目
  （与 printImage/printWholeImage 的 names 同构）；纯 shape → 丢弃（排版
  位移）。状态条 `体力[....](cur/max)` 的形态既有 gauge 分支已覆盖，未扩。

### 2. 观测面：与 Emuera 保存日志语义同构

Emuera 的保存日志 = **追加历史 + CLEARLINE 生效**（滚动出屏的行保留——
daycycle 三版主菜单全在样本里；原作 CLEARLINE 清掉的行消失——标题的 0
回显、翻页列表的中间版本）。ere 侧夹具 lines 是「全部 clear 生效」的净
效果，而主菜单自 #73 起就地重绘（ADR-0003，原作追加）——直接比对会把
ere 自建重绘清掉的旧版错算成几百条假差异。裁定（replay-b.js）：比对流 =
lines_history（只增不删）**剔除「与原作 CLEARLINE 对应」的清行**（保存/
读档画面 1:1 镜像原作清行的 era.clear）；自建清行（ScreenBlock 重绘、
set_story_name 的引擎约束清屏）删掉的条目**保留**。两类 clear 以调用栈
区分。

### 3. 输入通道与标记：模拟 Emuera 世界

- 输入全走 `useRule: false`（Emuera 的 INPUT 是自由输入；ere 引擎
  input() 只送达已打印按钮的快捷键——#129/#130 的实机差异。回放模拟
  的是 Emuera 世界，199/9999 一律可达；流程错位由比对层暴露）。
- 输入标记带 Row：原作的 CLEARLINE 清回显行（标题 0）在夹具 clear 的
  删行语义下同构消失；未清的（读档 99）保留。文本输入（INPUTS 故事名）
  的回显按 Emuera 形态标 **text**（黄金侧逐行无法区分回显与叙述）。

**比对抓到的两个真缺陷（当场处置）**：@SYSTEM_LOADEND 被 #136 误判死
代码（样本实证引擎在 LOADDATA 后自动调用它输出「兼容性修正中……」——
stub-registry 已勘误，移植随缺陷票）；save_game 漏抄原作 `:102` 的
「【保存存档】」前缀（已修复，`saveload-natural-log:90` 为证）。

## era.raw() 的裁决（变量层采集）

raw() 在引擎侧真实存在（app.asar 的 EraApi），但 **SDK 没有声明它**。
将来引擎删掉它时，游戏代码得到的是 `era.raw is not a function` 崩溃，而不是
SDK 的友好提示。本工具链离线运行、直接取夹具 store（内容等价于
`raw().data` 展平）；在引擎里采集时若 raw() 失效，备用方案是 `snapshot_via_get`
（经 era.get 遍历键清单重建快照，实现与测试都在）。引擎升版需复查。
