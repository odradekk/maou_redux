## 硬边界

## 三个设计裁定（工单留给本票的问题）

### 1. 对拍起点：手工播种等价角色，不解析 save00.sav

依据：

- 首回合的全部初始值**可从日志自身推导**。PALAM 初值 = 算式行 from 侧
  （`阴核 5240+300=5540`）；BASE 初值 = 回合后状态条 + 损耗回推
  （(1445/2000) + `-5`）；ABL / 素质 / 刻印 / CFLAG 由源一览与换算结果反解
  （`tools/compare/replay.js` 的种子表逐条注明证据行；推导表见文末）。
  8 条算式断言在回放的 before/after 两端全过（`test/compare-first-turn.test.js`），
  是「推导自洽」的机器证明。
- `save00.sav` 与日志窗口的**时间对齐关系不可知**：日志是同场次的尾部
  5000 行，存档是同场次的某一时刻——解析它得到的不是「窗口起点」。
- 二进制格式解析是独立工作量，解析器自身的 bug 会伪装成对拍噪音——
  #9 原型的静默截断缺陷就是这类。播种复用夹具既有机制，零新增采集面。

### 2. 录制器：复用 #16 夹具，不另造 print 代理

#9 原设「ere 侧包一层 print 代理、需要测试模式开关」是在夹具（#16）之前
定的。夹具已经是那个代理：加载真实 SDK、就地替换函数、游戏代码零修改。
再造第二个录制器会有两份「游戏输出了什么」的真相源。本票对夹具的唯一
改动是**补齐 print 系覆盖**（printMultiColumns / printInColRows / printImage
的逐格记录，加法式、全部既有测试不受影响）；输入标记由回放器在夹具之外
包装 `era.input` 压入 lines（输入不是输出，不属于夹具的职责）。

### 3. LCS 粒度与装饰行口径

- **粒度**：一「格」一条目——菜单行拆成 (标签, 编号) 条目、参数条网格拆成
  (键, 数值) 条目、算式行拆成数值四元组；text / input / calc / lossbar 走
  LCS（叙事次序是行为的一部分），menu / gauge 走集合比对（画面布局无次序
  语义，集合化即排版差异容忍的实现——检验2 重跑通过）。
- **装饰行**：空行 / 分割线 / 省略号整体丢弃。本分类器实测 5000 行样本：
  空行 260 + 分割线 462 + 省略号 364 = 1086 行（**21.7%**；#9 原口径 21.2%，
  差额是本分类器把 palam_up 的 31 字符短分隔线也计入 divider）。量级与
  结论不变：比对它们只产生噪音。

## #9 原型三项自检的重跑（植入位置另选）

原型三处是「文本加尾句、gauge 体力值、menu 爱抚编号」，本票另选（
`test/compare-diff.test.js`）：

1. **自比对零差异**：golden 窗口 vs 自身，0 条差异 ✓
2. **排版差异容忍**：菜单改单列、条形换宽换字符、算式空格重排、任意插
   空行——重归一化后 0 条差异 ✓
3. **植入 3 个缺陷全抓**：口上台词错字（温妮→温娚，log:25）、算式加数
   漂移且算术自洽（润滑 +61→+610、2854+610=3464，躲过自校验）、输入回显
   错值（0→2，log:21）——三条全部 unexplained 点名 ✓

## era.raw() 的裁决（变量层采集）

raw() 在引擎侧真实存在（app.asar 的 EraApi），但 **SDK 没有声明它**——
将来引擎删掉它时，游戏代码得到的是 `era.raw is not a function` 崩溃而非
SDK 的友好提示。本工具链离线运行、直接取夹具 store（内容等价于
`raw().data` 拍平）；实机采集若 raw() 失效，退路是 `snapshot_via_get`
（经 era.get 遍历键清单重建快照，实现与测试都在）。引擎升版需复查。
