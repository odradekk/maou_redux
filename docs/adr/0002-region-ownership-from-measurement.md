# 区段所有权：跨域读放行，跨域写具名

引擎变量表按「表 × 下标区段」划归玩法域：一个区段有一个属主域，域内读写自由，跨域访问按本 ADR 的规则处理。按表看没有局部性——每张变量表都被十几个目录读写；按区段看才有——各玩法域拥有自己的独占区段，真正的跨域流量集中在少数共享下标段。

划分登记在三处，全部进 git、归人工维护，检查器读它们：

- 「区段 → 属主域」：`ownership/<表>-ownership.yml`；
- 「`ere/` 目录 → 域」：`tools/domain-check.mjs` 的 `DIR_DOMAINS`；
- 跨域写的现有条目表：`tools/domain-ledger.mjs`（见下）。

## 跨域读放行，跨域写具名

跨域**读**高频且无害（口上必须读调教状态才能选台词），强制走方法会产出数万处样板。跨域**写**低频且是耦合的真实来源，逐条具名的工作量可承受：属主域 ≠ 所在文件的域即为跨域写，必须走属主域导出的具名方法（门面 setter）；裸字符串寻址的跨域写即红。

既有的裸跨域写冻结成只能变短的条目表（`tools/domain-ledger.mjs`，基线内嵌于 `tools/domain-check.mjs`）：条目表是「尚未迁移」的待办表，不是「可以这么写」的许可；代码多出即红（未登记的跨域写），代码少了也红（条目过期失效）。

不设「公共区」——公共区一定会长大，这正是当年 424 处裸寻址的形成机理。

## 为什么不凭直觉划定

按目录直觉划会得到错的边界——有的区段由多个域共写，不属于任何单一目录。登记在表里的划分可以被工具核对，口头约定不能；没有工具守着的约定会退化，#63 已经演示过一遍——`docs/skeleton.md` 写着「变量一律经包装层读写」，实测 424 处裸寻址。

## 域按 `ere/` 目录声明

每个域对应 `ere/` 下的一个目录，映射写在 `tools/domain-check.mjs` 的 `DIR_DOMAINS`。二次开发加域，就是新建目录并在映射里登记一行；未登记的新目录会被检查器报出，不会静默归进某个缺省域。`ownership/domains.yml` 是 #70 测量区段归属时用的输入数据，现在只作历史档案，没有工具读取它。

## 强制手段用独立检查器而非 ESLint 规则

检查器（`tools/domain-check.mjs`，由测试包装拉进 `npm test`）的形状：基线常量在工具本体、逐条豁免清单、明确的退出码语义。关键理由：**ESLint 的豁免机制是 `eslint-disable` 行内注释，它无法表达「清单只能变短」**，而那正是条目表需要的规则；基线常量能表达，且已被探针验证（偷加一条豁免 → 退出码 1）。

## 后果

- 九个域（八个玩法域 + patch）各拥有真实区段，无一域是纯客户端；低段共享状态按跨域写逐条具名，不构成并域证据。
- 几乎不写持久状态的跨域共享模块不参与区段归属，判断条件见 [ADR-0007](./0007-stateless-cross-domain-modules.md)。
