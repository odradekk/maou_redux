# 区段所有权由实测导出，不由人工划定

按**表**看，原作没有任何局部性：每张变量表都被十几个目录读写（`CFLAG` 12 个、`TALENT` 17 个），据此会得出「域所有权不可行」的结论。按**下标区段**重测，结论翻转——

| CFLAG 区段        | 写入者                               | 判定           |
| ----------------- | ------------------------------------ | -------------- |
| `2xx`             | 口上 1,057                           | 独占           |
| `3xx`             | 口上 8,650                           | 独占           |
| `5xx`             | 迷宫 145 / 侵略 57 / 角色函数 55 / … | 三域共有       |
| `1xx` `4xx` `6xx` | 混用，合计约 470 次写入              | 真正的跨域流量 |

`2xx`+`3xx` 是口上独占的 9,707 次写入、**零外部写入者**，占它全部 CFLAG 写入的 97%。**原作里已经存在事实上的私有区段，它只是没有任何手段表达或强制。**

因此：**「区段 → 属主域」「跨域写入清单」「域清单」三张表由离线脚本从 `target/` 实测产出**，进 git、归人工维护，与 `yml/` 同规格（产物边界规则同样适用：重跑默认跳过，重写须显式 `--force`）。

## 为什么不人工划定

按原作目录直觉划会得到错的边界——`5xx` 由迷宫、侵略、角色函数共写，不属于任何单一目录。而且 `target/` 是只读的，实测**可复算**：重跑脚本能验证划分没有被口头改掉。没有工具守着的约定会退化，#63 已经演示过一遍——`docs/skeleton.md` 写着「变量一律经包装层读写」，实测 424 处裸寻址。

## 域清单是产物，不是硬编码

二次开发会加域，加域不该改工具。清单落在产物表里，检查器读它。

## 跨域读放行，跨域写具名

跨域**读**高频且无害（口上必须读调教状态才能选台词），强制走方法会产出大量样板并被转译器复制近一万次。跨域**写**低频（约 470 次）且是耦合的真实来源，逐条具名的工作量可承受。

不设「公共区」——公共区一定会长大，这正是 424 处裸寻址的形成机理。

## 强制手段用独立检查器而非 ESLint 规则

照搬 `tools/trace-check.mjs` 的形状（基线常量在工具本体、逐条豁免台账、退出码语义），由测试包装拉进 `npm test`。关键理由：**ESLint 的豁免机制是 `eslint-disable` 行内注释，它无法表达「清单只能变短」**——而那正是存量 424 处需要的规则。#63 的 `ERB_EXEMPT_BASELINE` 能表达，且已被探针验证（偷加一条豁免 → 退出码 1）。

## 后果

现有的 8 个域（口上 / 调教 / 角色 / 据点 / 迷宫 / 侵略 / 事件 / 系统）**是在 CFLAG 一张表上得出的**。`TFLAG` / `TALENT` / `ABL` / `EXP` 的区段结构尚未测量，跑全表后域粒度可能被推翻——这正是域清单必须是产物而不是硬编码的原因。

## 勘误（#66 实施时发现，2026-08-19）

**本文开头那张证据表有三处错，全部出自本 ADR 作者手写的统计正则。决议不受影响，但数字要以 `ownership/` 的产物为准。**

1. **表里没有 `0xx` 一行，因为那段被正则漏掉了。** 用的模式要求百位数字后再跟两位（`0[0-9]{2}`），于是 0–99 这些两位数下标**一次也没匹配上**。实测该段有 **841 次实活写入、横跨 12 个目录**——是全表共享最重的一段，却在证据表里完全不可见。

2. **「跨域写约 470 次」是错的，实际 736 条。** 470 只是 `1xx`/`4xx`/`6xx` 三段之和；把漏掉的低段算进去后，跨域写入清单共 736 条。**结论不变**——736 仍然「小到可以逐条具名」，这是本 ADR 依赖的唯一性质。

3. **写入的判定口径本身有两处偏差**，均由 #66 查实并订正：
   - 漏掉**括号角色槽**形态（`CFLAG:(ARG:0):13 += 1`），约 430 次。计入后 `5xx` 的分布变成 迷宫 256 / 侵略 141 / 角色函数 55，侵略的权重接近翻倍。
   - 把**注释掉的死代码**计成写入，约 300 次，其中 260 次正落在 `2xx`/`3xx` 这个核心锚点内。

**核心锚点在订正后的口径下完好**：`2xx`+`3xx` 仍是口上独占、**零外部写入者**，9,707 → 实活 **9,447**（差值恰是那 260 条注释）。口上不使用括号形态，所以第 3 条的第一项不触及该锚点。

教训与 `docs/skeleton.md` 里那三类实机缺陷同源：**手写的一次性统计与工具产出的测量不是一回事**。本 ADR 之所以要求「实测导出 + 产物 + 可复算」，理由现在多了一条——它自己的证据就栽在手写统计上。

## 勘误二（#70 全表实测，2026-08-19）

全表 16 张表铺开后，#66 单表口径又被查出四处漏数，全部已修并重生成产物（对账见 issue #70 评论）：

1. **表名无词边界**：`EX_CFLAG:A:99 = CFLAG:A:800` 里的 `CFLAG:A:99` 被记成 CFLAG 写入（实测 2 笔假写）。`EX_CFLAG`/`EX_FLAG`/`EX_TALENT`/`LOSEBASE`/`NOWEX` 等都是 `#DIM` 自定义变量或引擎内建变量，不是引擎表。
2. **寻址段不含 CJK**：`CFLAG:L_孩子:1 = 0`（CJK 名变量做槽位）的 4 笔写入被记成读。
3. **五类写形未计**：字符串赋值 `'= `、后缀 `++`/`--`（#66 的负检查只对 CFLAG 字面量形态成立，`CFLAG:ARG:131++` 即漏网）、`TIMES` 乘法赋值（SOURCE 上 3,860 处）、`VARSET` 区间写、CJK 名字下标（先归一再查名字表，1005 处用法）。
4. **ignored_files 守卫改判**：「忽略文件出现写入即报错」不成立——TITLE.ERB 是引擎不装载的死代码（issue #12 的同名冲突仲裁），它写 GLOBAL 与测量无关；改为「整体跳过测量 + 声明的文件必须存在」。

订正后 CFLAG：实活写入 11,435 → **11,439**、读取 15,543 → 15,529、注释写 305 → 307、区间 106 → 104、跨域写 736 → **740**。**口上锚点纹丝不动**：2xx+3xx 仍独占、仍 9,447、仍零外部写入者。全表口径下八域 + patch 的划分经实测成立（每域都拥有真实区段，无一域是纯客户端），域清单在 `ownership/domains.yml` 定稿；全表跨域写共 **2,652** 条——「低频、小到可以逐条具名」的结论在 16 张表上仍然成立。
