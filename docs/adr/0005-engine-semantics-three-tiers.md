# 引擎语义的三层可达性：能执行的对拍，能读的锚定，都不能的写下来

夹具（`test/helpers/era-fixture.js`）是全项目唯一的缝，它对引擎语义的镜像此前只有**人读 `app.asar` 后写下的注释**背书。同一缺陷类连中三票——查实了、写进注释了、没镜像进夹具，于是测试全绿而实机出错：

| 票  | 事实                                          | 后果                                    | 发现方式                     |
| --- | --------------------------------------------- | --------------------------------------- | ---------------------------- |
| #68 | `input` 回显占 1 Row                          | 组件按跨度清行时每轮净涨一行            | 验收（发回整改）             |
| #69 | `playMusic` 不调 `addTotalLines`，**不占 Row** | Row 记账错位                            | 验收（495 条测试全绿放过一版） |
| #74 | `barWidth` 缺省 24 时条后文字整列 `display:none` | 实机上每个参数数值消失                  | 验收（528 条测试 + 对拍全绿） |

三次都在验收时靠人读引擎源码抓到。**注释不会在回归时说话**——但引擎语义并非都能交给工具，可达性分三层（`ere-4.8.0` 实测）：

| 层  | 内容                                                                                        | 位置                                                              | 守法                                       |
| --- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------ |
| 1   | `addTotalLines` / `setTotalLines` / `waitAnyKey` / `getLineCount` / `clear` 守卫链——`allowWait` 状态机整个在内 | `background.js`，`engine-bundle` 已加载并暴露 `era_api`（模块 183） | **逐步契约对拍**：真方法 + 假 this         |
| 2   | `get*Object` 七个行对象变换（`getProgressObject` / `getButtonObject` / `getTextObject` …）   | 渲染包 `js/app.*.js`，源码形态只存在于 source map                 | **锚点校核** + **调用点规则**              |
| 3   | Vue 模板后果（`:span="24 - line.barWidth"` → `el-col-0` → `display:none`）                   | `app.vue` 模板                                                    | **不可覆盖**——只有人读与实机验收           |

因此：**第一层做逐步契约对拍；第二层锚定其源码文本并在调用点立规则；第三层写下来，不假装能守。**

## 为什么

第二层为什么不能执行——这条最反直觉，也是本 ADR 存在的主要理由：

- 变换函数住在 `src/renderer/app.vue` 里（1157 行 Vue SFC），`import` 了 `element-plus` / `vue` / `vue-chartjs` / `chartjs-plugin-annotation` 与多个本地组件；
- 它们**不自洽**——`getValidValue` 在另一个文件；
- 出货形态是混淆过的（`getProgressObject` → `J(e)`），可读形态只在 `.js.map` 的 `sourcesContent` 里，那是源码映射，不是可加载模块。

所以「把 `engine-bundle` 接到渲染层」这个看似显然的做法**不成立**。退而求其次的两件事各守一头：**锚点校核**断言引擎源码里仍含 `barWidth: data.config.barWidth ?? 24` 这类字面——引擎升版改了默认值时它说话，守的是「引擎还是不是这样」；**调用点规则**守「我们有没有踩上去」。两者共享同一张引擎事实表，因为同一条事实既是锚点的断言对象，也是规则的阈值来源。

夹具**不委托**引擎、保留自己的镜像，另加契约测试对拍——因为 `engine-bundle` 的既定语义是「引擎缺失时依赖它的用例 `test.skip` 退场，不该让裸克隆连 `npm test` 都跑不过」。委托会让每一条用到夹具的测试都变成引擎依赖。对拍还多留下一个可断言的对象：委托之后镜像消失，也就没有东西可红。

**逐步对拍而非末态对拍**：三次缺陷的共同形态是「某一次调用的副作用被漏掉」，末态对拍在多次调用互相抵消时会静默通过。

## 后果

**新工具独立于 `trace-check`，不并入。** 两者都用锚点，但失配的含义相反：`trace-check` 的锚失配意思是「我们的行号写错了」，引擎锚失配意思是「引擎变了、我们的镜像要重核」。处置动作不同，混用会让退出码语义变糊。

**引擎缺失 → skip；模块号或锚点漂移 → 硬红。** 缺引擎是环境事实（裸克隆合法）；漂移则正是镜像最需要被重核的时刻，静默 skip 会让守护在升版当天无声消失。渲染包文件名带内容哈希（`app.2cccec57.js`），定位器必须是模式匹配。

**事实表只收「夹具行为真的依赖它」的条目。** 判据是可断言性：能同时喂给锚点校核与调用点规则的才是事实，喂不动的是叙述（例如「引擎主/渲染两层在 0 行时分歧」属背景知识，不进表）。

**第三层的空缺是永久的。** 下一次架构复盘很可能又提议「直接驱动引擎渲染层」——上面三条实测是它不成立的依据。第三层只能靠实机验收，这也是每张表现层票都要求实机步骤的原因。
