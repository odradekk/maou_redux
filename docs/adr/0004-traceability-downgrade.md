# 追溯注释降级：手写函数级，生成行级

手写的行级追溯引用（`// :N`）腐烂是**结构性的**，同一缺陷类已经出现三次：

| 票  | 偏移                 | 发现方式                                                                              |
| --- | -------------------- | ------------------------------------------------------------------------------------- |
| #44 | 2–30 行              | 事后审计                                                                              |
| #48 | 1–3 行，且随位置递增 | 验收抽查（29 条里 26 条错）                                                           |
| #63 | 1–5 行               | 派发前实测（`page-main-menu.js` 45 条里 7 条错，其中 `:48` 指着一行被注释掉的死代码） |

三次都是「已经错了一大片」才发现。#63 给它上了闸（未登记即红），但闸只保证**引用被登记**，不能让人写得更准。

因此：**手写代码只写函数级或区间级追溯**（文件头的「源: …@函数名」保留不变）；**精确到行的引用由转译器在转换时自动生成**。现有的 465 条豁免清单维持只减不增。

## 为什么

机器生成的引用不会腐烂——它在转换的那一刻就知道行号从哪来。人写的会：手要在两个文件之间来回数行，而源文件的行号在移植期间对人来说是不可见的。让工具承担精度，让人承担更粗、更不容易错的粒度。

这不削弱追溯：函数级已经足够定位（`docs/skeleton.md`：「追溯靠文件头注释，不靠目录镜像……这比目录镜像更准，且不受重构影响」），而错的行级引用**比没有更糟**——它会把审校者带到另一段逻辑上。

## 后果

**这条最容易被后来者当成偷懒而改回去。** 上表的三次实证是它的依据，改回去之前请先解释怎么避免第四次。

`trace-check` 的在册校验（引用与源文件比对）与完整性检查（未登记即红）都不变，只是新增的**手写**引用不再要求精确到行；转译器产出的引用照常登记并校验。
