# 引擎变量表是唯一真相源，门面按域分组

引擎允许变量槽存放任意 JS 类型（`dev-guides/09-static.md`「变量数据表」一节），这诱使我们建一套并行的 JS 领域对象模型来承载状态。**我们不这么做**：存档序列化的就是引擎数据表（`era.saveData` 保存的是 global 表之外的数据表，`dev-guides/11-saves.md`），并行对象模型会造出两份真相，而两份真相是这个项目能犯的最贵的错误。

因此：**引擎变量表是唯一真相源**，所有读写经门面，门面**按玩法域分组**且一维二维对称——

- 二维角色变量：`chara(cid).<域>.<字段>`
- 一维系统变量：`game.<域>.<字段>`

门面是生成的 class（无 Proxy，纯属性访问），`chara(cid)` 返回按角色 ID 缓存的单例视图（只持 ID，不持值，getter 直落 `era.get`）。

## 为什么按域分组而不按表分组

现状的 `era_flag` 是一个扁平的全局命名空间，把 `flag:36`（据点主菜单的面板选择）和 `tflag:*`（调教域）放在同一个对象里——**没有边界可言，工具也无从强制**。按域分组之后，`chara(cid).train.*` 出现在口上文件里就是一处显式的跨域调用，检查器抓得住（见 [ADR-0002](./0002-region-ownership-from-measurement.md)）。

## 为什么不是纯函数加常量表

口上转译器会把门面的调用形式**机械复制约一万次**（实测：口上写了全游戏 88.5% 的 CFLAG，9,969 次）。判据是「审校者手边摊着 ERB，能不能一眼确认这行对不对」——口上产出要人工逐段复核约 25,000 段。`chara(cid).kojo.已说过第三句 = 1` 对得上 `CFLAG:TARGET:322 = 1`；`set(cid, CFLAG.x, 1)` 对不上。

## 新字段落在自造扩展表

二次开发新增的字段一律走引擎的自定义扩展表（`system.extendedCharaTables`），**不占原作表的空闲区段**。原作的「空闲」不可信——`target/` 里 `魔改新增`、`MOD`、`DEBUG小白娘2024ver0.0.14` 三个后加目录已经在占用高位下标。分表存放让存档 diff 一眼分得出「移植的」与「我们加的」，这是二次开发最需要的一条边界。

## 硬约束：扩展表必须在存档产生之前落地（#67 实测的引擎缺陷）

引擎 `fillData` 里为扩展表重建 per-chara 桶的分支是**恒假死代码**：

```js
Object.entries(this.era.extendedTables).filter(e => void 0 !== this.staticData[e[0]])
  .forEach(([e, t]) => {
     t === tableType.normal ? /* 一维分支用 t，对 */
                            : e[1] === tableType.chara && /* 二维分支用 e[1]，错 */ … })
```

`e` 是表名字符串，`e[1]` 是它的第二个字符——`'portcflag'[1] === 'o'`，永不等于 `2`。应为 `t === tableType.chara`。

**后果**：一张**晚于存档出现**的二维扩展表，对该存档里已有的角色不会重建数据桶。此后这些角色的三段寻址写入**静默丢弃**——而且**游戏代码修不了**：名字表在、桶不在这一组合的语义就是静默丢弃，所以 `era.set` 补不出桶来；能建桶的 `addCharacter` 会连带重置该角色的全部数据，不能用作迁移。

因此本 ADR 的「新字段走自造扩展表」附带一条时序约束：

- **发布前**：新增扩展表随意，`fillData` 的缺陷够不着。
- **发布后**：给**已存在的**扩展表加字段是安全的（字段是名字表的行，桶已在）；**新增一张表**则对老存档里的角色不可用。

实践含义：**宁可先立一张宽的表，也不要事后开新表**。`portcflag`（#67）就是按这条立的——它是移植自建字段的**唯一**落点，新字段加行不加表。

该行为由 `test/portcflag-table.test.js` 用真 `EraApi` 如实钉住（删桶 → `fillData()` → 顶层重建为 `{}`、per-chara 不重建 → `set`/`get` 双双 `undefined`）。引擎侧若哪天修了这个 bug，那条用例会红——那时来改本节。

## 后果

- 门面接口一旦被转译器复制，改动成本极高——**形状必须在转译器上场前定稿**。
- 既有 466 处变量访问里 424 处是裸字符串寻址（包装层只覆盖 `flag` 与 `global`，42 处）。存量随票迁移、冻结成只能变短的台账，不一次性大修。
- `ere.config.json` 的 `extendedCharaTables` 目前是 `[]`，这条路一次没走过，得先用一张小表跑通。
