# 无域状态的跨域模块不参与区段归属

ADR-0002 定下「区段所有权由实测导出，不由人工划定」，判据是**写入区段所有权**。#134 的装备与服装裁定撞上一类该判据无法回答的文件：**几乎不写持久状态的跨域共享模块**。

`target/ERB/其他/EQUIP.ERB` 是首例（1114 行、13 个函数）：

| 度量                                   | 数值                                                                                |
| -------------------------------------- | ----------------------------------------------------------------------------------- |
| 持久写入                               | **6 处**（`CFLAG` 2 / `ITEM` 4）                                                    |
| 局部数组赋值（`W:n`）                  | **300+ 处**                                                                         |
| 全库真 `EQUIP:` 寻址（排除 `TEQUIP:`） | 全库 **6 处**，且不在本文件内                                                       |
| 调用者域                               | SYSTEM / キャラ関数 / 侵略 / 迷宮 / SHOP / 其他 / 處刑相關 / 魔改新增，**无主导者** |

对照组 `FUNC_CLOTH.ERB`（同目录、行数相近）有 50 处 `CFLAG` 持久写入，测量给出 train 且与函数语义（`AFTERTRAIN_CLOTH` / `SOILING_CLOTH` / `WASHING_CLOTH`）吻合——**信号强弱不是这两个文件的区别，有没有域状态才是**。

因此：**当一个文件几乎不写持久状态时，ADR-0002 的判据对它不适用。裁定为「不属任何玩法域」，回落兜底域，并在 `ownership/domains.yml` 显式注明这是裁定结果而非默认兜底。**

## 为什么不是「信号薄」

#133 的测量报告把 `EQUIP` 记为「3 票 2:1，票据极薄」，`USE_EX_ITEM` 记为「30 票 16:14，同样薄」。**这两者性质不同**：

- `USE_EX_ITEM` 有 30 处真实持久写入，16:14 是**势均力敌**——判据成立，只是差值小。它的归属（dungeon）维持采纳。
- `EQUIP` 只有 6 处持久写入，其中 4 处还是 `ITEM`。2:1 不是「差值小」，是**样本几乎不存在**。

把两者都叫「票薄」会诱导出同一种处置（再测一次、或按 plurality 硬裁），而正确处置不同。判据不适用时再精确的测量也不会产生信号——#133 已经重跑过一次全量测量，结论仍是 2:1。**不写下这条，下一个碰到同类文件的人还会再测一遍。**

## 为什么不新建 equip 域

引擎侧有 `equip` 表的位置（`addCharacter` 会为它建桶），但原作不写它，`yml/` 因此没有 `Equip.yml`，而 `tools/ownership-scan.js` 的 `TABLES` 由 `yml/` 里存在的名字表决定——**equip 现在没有任何区段可归**。

一个没有自己区段的域会违反 #70 定稿时确立的事实（九域「每个都拥有真实区段，最少的 invasion 6 段 / patch 5 段，无一域是纯客户端」），也会让 `domains.yml` 的语义从「实测产物」滑向「人工分类」。

**但扩展点是真实的**：二次开发若建 `yml/Equip.yml` 并引入 `EQUIP:` 写入，equip 立刻获得真实区段，那时按 `domains.yml` 顶部的说明新建域即可，工具零改动。已在该文件的 `system` 块注明。

考虑过并否决的另一条路是「按调用者 plurality 硬裁」：实测调用者分布在六个域以上且无主导者，结果等同掷硬币，而掷出来的域会在跨域写清单里产生一批虚假的耦合记录。

## 域归属与代码落点是两件事

裁定期间澄清的一个混淆：

|          | 载体                    | 寿命                             | 服务于                 |
| -------- | ----------------------- | -------------------------------- | ---------------------- |
| 域归属   | `ownership/domains.yml` | 移植期，路线图阶段 7「断缆」拆除 | 「这段原作代码搬到哪」 |
| 代码落点 | `ere/` 目录结构         | 永久                             | 后续开发与二次开发     |

`EQUIP` 不属玩法域，**不意味着它在 ere 侧没有位置**。它的落点定为 `ere/system/equip/`（`AGENTS.md` 允许 `system/` 按域再分子目录），理由是它是一个内聚的子系统（13 个函数、六域共用），二次开发最可能扩展的方向之一就是装备。为二次开发留位置应当留在代码结构里，而不是留在一个计划拆除的产物文件里。

## 对 ADR-0002 的关系

**补充，不是推翻。** ADR-0002 的「不人工划定」仍然成立——本 ADR 没有人工指定任何域归属，而是判定「测量对该文件无法给出归属」。导出规则本身未改：`node tools/ownership-scan.js --export 其他` 仍会算出 `EQUIP.ERB → event`，**工具照算，人不采纳**。这一对关系由两条测试分别钉住（`test/ownership-scan.test.js`）：

- 「清单里不得有 `EQUIP.ERB` 声明」——钉裁定；
- 「`--export` 仍算出 event」——钉工具未被裁定改动。

## 后果

- `EQUIP.ERB` 的 2 处 `CFLAG` 写入从域内写变为 `system → event` 跨域写，全表跨域写 2475 → **2477**，CFLAG 跨域 675 → **677**。锚点已更新。
- 「装备与服装是一件事」（#106）**作废**：`FUNC_CLOTH` 归 train 随阶段 4，`EQUIP` 无域归属、移植票排阶段 3（消费者侵略与迷宮在那里）。
- 本 ADR 的判据可复用：今后出现「持久写入寥寥、调用者遍布多域」的文件，按此处置，不必再测一轮。
