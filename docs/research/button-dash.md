# 按钮正文的「- 」分隔符普查（`[N] - 正文` → `printButton`）

对应工单：[issue #612](https://github.com/odradekk/maou_redux/issues/612)（来源：#595
验收时在引擎里看到能力提升画面）。前一轮同类修补是 #572（纯文本编号选项按钮化时
顺带补回 23 枚），本票把剩下的画面逐个过完。

## 一、结论摘要

1. **病灶**：原作把选项编号与正文写在同一行（`PRINTL [100] - 停止`，`- ` 是**正文
   的一部分**）；移植成 `era.printButton(正文, 编号)` 后引擎按 `showAcc` 自己拼
   `[编号] `，正文里不写 `- ` 就显示成 `[100] 停止`。golden 样本是判据：
   `golden/train-natural.log:959-960` 是 `[0] - 阴核点数×5859/20000 ……点数不足 `
   与 `[100] - 停止`，本票前移植版渲染的是 `[0] 阴核点数×…` / `[100] 停止`。
   既有口径见 `ere/page/page-ability-up.js` 的文件头；**正文不写 `[N]` 前缀**是
   AGENTS.md 的硬约束（PR #30 实机撞见 `[0] [0]`），本票只补分隔符、不碰编号。
2. **普查规模**：`target/ERB` 全目录里带 `[N]` 编号点的 PRINT 族语句共切出
   **1646 条选项**；`ere/` 全目录的按钮（`printButton` 与 `printMultiColumns` 的
   按钮格）共 **852 枚**。两两配对成功 **716** 对。
3. **本票修掉的**：**16 个文件、198 枚按钮**补回分隔符（逐文件见第四节表 A）。
   其中 191 枚是正文直接改动，另 7 枚经 `option0/option1/option2` 变量间接改
   （ablup.js 的 ABLUP6/8/9 三处选项串，变量声明处补一次即可）。
4. **配对成立且已带「- 」的**：677 枚（表 B）——这些是 #572 与更早已补过的，
   本票只核不改。
5. **原作侧没配上按钮的 991 条**（表 C）：大部分是**尚未移植**的子系统
   （`SHOP_LABO` 的改造菜单、`COMF110` 穿脱衣服、`SHOW_ITEM` 大菜单等），
   小部分是**有意保持纯文本**的界面（#180 的逐层 WAIT、`useRule: false` 的消费点，
   见 `docs/research/plaintext-options.md`）。这些票在移植对应界面时按本报告
   的配对办法自查一遍即可。
6. **一处需要说明的口径**：原作 COMF73\_髪型を弄る.ERB 的分隔符写成 **`---`**
   （三个连写破折号，且不带空格；`:145/:147` 起还有 `--`），与本票主线的 `- `
   不同形但同源——移植版原来整个丢了。按 1:1 照写原文（`'---自然'`、`'--侧束发'`），
   com-assistant.js 的注释里记了出处。**这不是笔误**：同一文件里 `[1]-9` 用
   `---`、`[10]-12` 用 `--`，是原作自己的对齐写法。
7. **九份输出比对样本**：改动前后各跑一次，`train-natural` / `train-upgrade` /
   `sale-natural` 三份里原本因缺分隔符产生的菜单差异按 #612 的账结清（详见工单
   完成评论与 `tools/compare/rules.js` 的规则注释）。

## 二、判定面与配对办法（`tools/button-dash-scan.mjs`）

```
node tools/button-dash-scan.mjs          # 打印配对结论
node tools/button-dash-scan.mjs --json   # 机器可读（同一份数据）
```

**原作侧**：扫 `target/ERB/**/*.ERB`，按 PRINT 族的**逻辑行**取选项。逻辑行 = 一串
不换行的 PRINT 语句（`PRINT` / `PRINTS` / `PRINTV` / `PRINTFORM` / `PRINTC` …）＋
收尾的换行语句——原作常把一条选项拆成好几条语句（ABLUP6.ERB:109-135
`PRINT [0] - ` / `PRINTS PALAMNAME:6` / `PRINT 点数×` / `PRINTV A` …），只看单行
会漏掉正文。`PRINTS` / `PRINTV` 打的是变量，按占位符计。

**ere 侧**：扫 `ere/**/*.js` 的 `era.printButton(…)` 与 `printMultiColumns` 里
`{ type: 'button', content: … }` 的 `content`。正文取**字面量骨架**：插值换成占位符、
空白压平、注释跳过；间接实参（`option0` 这类裸标识符）回溯同文件里的赋值拼出骨架。

**配对**（三道，依次放宽）：

1. 核心字面量相等或一方含另一方（含 `- ` 与不含 `- ` 两种剥法各比一次）；
2. 兜底：按钮骨架里最长的字面量段（≥4 字符）出现在原作正文里——原作写死数字、
   移植侧是插值的情形（`[0] - 日常服饰（100点）` vs `` `日常服饰（${CASUAL_PRICE}点）` ``）
   靠这条接上；
3. 编号一致优先：`printButton` 的第二实参与原作 `[N]` 相同者优先，编号都要不上时
   落进「需人工判号」清单人工看。

判定面有意收窄的几处：

- 注释掉的选项行（`;PRINTL [6] - …`）不是可执行语句，不算；
- 行尾形态的 `PRINTC 能力表示[100]`（编号在末尾）不是「编号在前」的选项，不算；
- `[ N]` 定宽补位、`[N] - ` 之后的空格数不在本票范围（编号与空白由引擎渲染）；
- `COMF90_ニプルファック.ERB` 是 Shift-JIS，按 UTF-8 读会带替换字符，**跳过并
  在报告里点名**——不让「读不了」悄悄变成「扫过了、没有」。该文件里没有
  `[N] - ` 形态的选项行，跳过不影响结论。
- 比对前两侧都过一遍 `tools/lang-normalize.js` 的 `to_simplified`（原作是繁体/日文
  新字体混排，移植版一律简体），中点 `・`/`·`/`･` 也归一——否则
  `[9] - 向著世界之外` 与 `'向着世界之外'`、`（资金・俘虏）` 与 `（资金·俘虏）`
  对不上，那几屏会整批落进「没配上原作」而漏判。

### 3.3 `- ` 的形式差异

- **`---` / `--`（COMF73）**：见结论第 6 条，按原文照写。
- **破折号后的空格**：原作 `[N] - 返  回` 的空格数由引擎的空白折叠规则决定
  （`printButton` 会把正文里的连续空白并成一个空格），移植版写 `- 返 回` 即为
  折叠后的终态；`[N] -  正文`（两个空格）一律写成 `- 正文`。这一维是本票的
  有意不动项。

## 五、重跑与守护

```
node tools/button-dash-scan.mjs            # 全库配对结论
node tools/run-node.mjs -- --test test/ablup.test.js
```

- **本票的守护在测试与变异条目里**：每个改动的画面都有一条 `rendered`
  （`[编号] - 正文` 的渲染终态）断言；`tools/mutations/` 里对应的条目去掉 `- `
  会让该断言变红。工具本身**不设棘轮基线**——判定面依赖两侧文本骨架的启发式
  比对（编号漂移、数据表拼串、跨函数复用的变量都会落进「未配上原文」桶），
  把那些噪声冻成基线会挡住后续正常改动；要盯「新出现的缺分隔符」，用本工具
  重跑、看「缺分隔符的按钮」那一节是否为 0 即可。
- `rendered` 是**引擎渲染后的样子**（`[编号] 正文`，空白折叠成一个空格），
  断言按钮外观一律看它；只看 `text` 会漏掉手写编号前缀撞车（PR #30 的
  `[0] [0] 旧的奴隶`）。
