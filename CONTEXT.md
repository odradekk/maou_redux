# CONTEXT

《魔王 Redux》的术语表。

本表记录游戏概念与引擎 API 的术语对应，供命名和编写文档时查阅。

命名（标识符、测试名、issue 标题、提交信息）时使用本表的「本项目用词」一列。表中没有的概念，应确认是否应使用已有用词；确有新增概念时，再补充本表。

## 记法约定

- 引擎 API 与寻址字符串保持引擎规定的大小写：`era.printButton`、`flag:36`。

## 写作约定

文档、注释、测试名和 issue 一律使用常用工程术语，避免行业外比喻、网络用语和临时造词。下表列出应避免的表达及其按语义可选的替代说法；写作时应根据上下文选择准确的词，不作机械替换。

| 不用                                 | 改用                                                   |
| ------------------------------------ | ------------------------------------------------------ |
| 台账、对账、在账、销账、欠账、收账   | 条目表、清单、核对、待办项                             |
| 口径                                 | 判定标准、统计方式、版本                               |
| 留痕、定档、存量、发霉               | 记录、定稿、现有、过期失效                             |
| 点名、靶向、门控、守门、网住         | 报出位置、指向、需要引擎、阻止                         |
| 钉死、接线                           | 用回归测试固定、接入                                   |
| 假绿、硬崩、硬红                     | 误报通过、直接崩溃、直接判失败                         |
| 档（快档／全量档）、硬口径、弱路径   | 模式、严格标准、宽松判定                               |
| 三件套、换皮、铺开、一键、复跑、两相 | 三项自检、替换表现层、推广到、一条命令、重跑、两个阶段 |
| 曳光弹、测试缝、对拍                 | 端到端验证、测试注入点、输出比对                       |

「门面」「归一化」「状态机」「测试夹具」是标准领域术语，可以保留；首次出现时应说明其在本文中的具体含义。其他词按实际行为表述，例如写清默认处理或回退条件，不用泛化的「兜底」。

## 架构术语

决策见 `docs/adr/`。这些词是本项目自建的，引擎没有对应物。

| 用词         | 含义                                                                                                                                                                                                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 域           | 玩法维度的所有权单元：口上 / 调教 / 角色 / 据点 / 迷宫 / 侵略 / 事件 / 系统。一个域拥有若干变量区段；清单是 `ownership/` 里的一张表，不是硬编码枚举                                                                                                                             |
| 门面         | 变量访问的入口，按域分组，并为一维和二维变量提供对称访问方式：`chara(cid).<域>.<字段>` 与 `game.<域>.<字段>`。使用生成的 class，不使用 Proxy；字段名用中文；`chara(cid)` 按角色 ID 缓存单例视图。既有扁平 `era_flag` / `era_global` 并存，一维变量不强制迁移                    |
| 区段所有权   | 「某段变量下标归某个域」的映射，登记在 `ownership/`，人工维护                                                                                                                                                                                                                   |
| 无域状态模块 | 几乎不写持久状态、被多个域共用的文件。区段所有权判据对它**不适用**，因此不归入任何玩法域，归入无域状态模块，见 ADR-0007。首例是装备模块（`ere/system/equip/`）。与之相对，服装模块有大量持久写入（#134 的测量为 50 处），判据成立                                               |
| 跨域写       | 一个域写入另一个域拥有的区段。允许，但必须经属主域导出的具名方法；**跨域读不受限**                                                                                                                                                                                              |
| 一屏         | 从玩家一次菜单选择开始，到下一次需要玩家做菜单选择为止的全部输出。菜单选择后的结算与口上逐行等键都在同一屏内累积，不因按键被清掉（ADR-0009）                                                                                                                                    |
| 换屏         | 每一屏开始绘制前整屏清空（无参 `era.clear()`），统一入口是 `ere/page/components/screen-change.js` 的 `change_screen`，不保留历史（ADR-0009）。换屏不补等键；换屏前的输出必须已经过玩家按键确认，漏补等键由测试夹具的未读输出检查（`unread_output_clears`）报出                  |
| 画面组件     | 已删除的概念（#724）：曾是「自知占几行、可就地重绘的屏幕块」，换屏规则（ADR-0009）推广到全部页面后无剩余调用方。历史与设计理由见 ADR-0003、ADR-0009                                                                                                                             |
| 重绘         | 整屏清空后整屏重画，发生在每一屏开始（ADR-0009）。**只发生在玩家交互之后**：叙述流中间清屏会打断玩家的右键快进，换屏正是快进的翻页点                                                                                                                                            |
| 引擎事实     | 引擎对参数执行的一次变换，且**测试夹具的记录行为依赖它**（如 `barWidth` 缺省 24 会让条后文字整列不渲染）。将该事实写入表中，同时供锚点校核（检查引擎是否变化）与调用点规则（检查调用是否满足条件）使用；两者都不使用的内容属于背景说明，不算引擎事实。可达性分三层，见 ADR-0005 |

**「行（Row）」是引擎的编程行，不是显示行。** 一次 `printMultiColumns` 无论输出几个格子都只占一个 Row，`clear(1)` 会把它们一起清除；而一段长文本自然换行成三个显示行时仍只是一个 Row。局部清除（`clear(n)`）与运行时行数测量（`getLineCount`）计的都是 Row 数。

## 输出 API 的排版与对齐

**引擎的 `printButton` 自成一行。** 由此两条推论：

- 一组选项按钮之后**不再补空行**；只有真正要空行时才写 `era.println()` / `era.print('')`，多补一条就是多出来的空行（#562）。
- 想在一行排多个按钮时，每个按钮仍各占一行。少数界面用 `era.setAlign('center')` 或 `printButton` 的 `align` 近似列感（`ere/page/page-item-shop.js` 与 `page-shop-trap.js` 的页脚就是这种写法）。

**选项按钮的正文以 `- ` 开头**，引擎拼出 `[N] ` 前缀后显示为 `[N] - 正文`。例外不逐处改齐：剪发菜单的分隔符是 `---`/`--`（`ere/system/train/com-assistant.js`）；部位菜单（`block_feeling`，`ere/page/page-shop-labo.js`）的选项不带破折号；空存档槽的 `----` 整串是正文（`ere/page/page-save-load.js`）；列表页脚的翻页键不带破折号。

**对齐补位用 U+00A0（不换行空格），不用半角空格（#577）。** 引擎渲染层对文本行没有 `white-space` 设置，连续半角空格按浏览器默认规则合并成一个——模板串里的空格补位在实机上全部失效。对齐补位一律走 `#/utils/display-width` 的 `pad_display` / `pad_left`（补位字符 U+00A0，源码以 `\u00A0` 转义或 `NBSP` 常量书写，不写裸字符）；引擎等宽字体下 U+00A0 占 1 个半角宽。两条边界：

- 只为分隔而写的单个半角空格不动；行尾与整行空白不动。
- **按钮正文不能靠 NBSP 对齐。** 渲染层的按钮行构造器（`app.asar` 的 `js/app.*.js`，构造 `lineType.button` 的 `function P(e)`）会把正文预处理成 `(!1 !== showAcc ? '[' + acc + '] ' + content : '[' + content + ']').split('\n').map(s => s.replace(/\s+/g, ' '))`——`showAcc` **缺省为真**（只有显式传 `false` 才不拼编号前缀；编号前缀由引擎拼，按钮正文不得自行添加，见 AGENTS.md），而 JS 的 `\s` 连 U+00A0、U+3000 一起匹配：按钮正文里的**任何**空白补位都被引擎自己压成一个半角空格（#577 之前用半角空格补位也是同一结果，实机表现不变）。**`printMultiColumns` 里的按钮格走同一条构造器**（多列按格的 `type` 派发），同样不能靠 NBSP 对齐；text / progress / divider / image 格不经过它。这类位置**整体**不处理、不逐处列举：按钮正文里手写的空白（存档槽位的备注 `page-save-load.js`、种族年龄配置页的档位按钮 `page-config-age.js`、实验室与设置页的价格列 `page-shop-labo.js` / `page-config.js` 等）一律不动——改也白改。`#577` 的普查表（逐文件的原写法与处理）见该 issue 的完成评论。

## 三条容易误解的语义

**转场不是立即跳转。** 发出转场后，当前函数立刻结束，但事件链**继续跑完剩余的处理器**；期间若再次发出，后者覆盖前者，最后一个生效；整条链退出后才真正切换状态。按「立即跳转」实现会静默跳过大段结算逻辑。

**写入未声明序号的行为，取决于名字表和数据容器是否存在。** 名字表指 `yml/` 中的静态表，数据容器指引擎保存该类变量值的 `data` 对象。两者都存在时，未声明下标按数字处理并成功写入；只有名字表时，写入被静默丢弃；**只有数据容器时，写入直接抛错**。两段和三段地址都遵循此规则。确认一种变量能写入，不能证明其他变量也具备所需的表和数据容器。

**「已加入序号」与「角色 ID」不等价。** 本项目一律用角色 ID 寻址；判断角色是否在队，须按语义写成「不在已加入列表中」，不能用序号大小比较代替成员判断。
