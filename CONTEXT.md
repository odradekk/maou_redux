# CONTEXT

《ERA魔王 年度版》移植项目的术语表。

这个项目横跨**三套词汇**：日文原作（eramaou 及其 Emuera 血统）、简体中文汉化层、EraElectron 引擎的英文 API。同一个东西常有三个名字，且三者并非一一对应——`素質` 在汉化里叫「素质」，在引擎里叫 `talent`，而中文语境下「素质」还可能指别的东西。缺一份对照会持续产生歧义，尤其在写 issue 标题与测试名时。

**用法**：命名（标识符、测试名、issue 标题、提交信息）时用本表的「本项目用词」一列。表里没有的概念是个信号——要么在发明项目不使用的语言（重新考虑），要么是真实的空白（补进本表）。

## 记法约定

- 原作的变量与函数按 Emuera 原样大写书写：`FLAG:36`、`@EVENTFIRST`。
- 引擎 API 与寻址字符串按引擎原样小写书写：`era.printButton`、`flag:36`。
- 两者对照时先写原作、后写引擎：`GLOBAL:99` ↔ `global:99`。

| 角色旗标     | `CFLAG`                                  | `cflag`               | 角色维度的杂项状态，二维                                                                                                                                                             |
| 移植角色旗标 | —（原作无，移植自建）                    | `portcflag`           | 移植版自建的二维扩展表（#67）：二次开发新增的按角色字段一律落此，不占原作表的空闲区段。名字表 yml/PortCFlag.yml，登记 yml/\_fixed.json；首字段「数据版本」＝该角色数据的移植口径版本 |

**`callname` 的两个负数下标**：引擎在 `addCharacter` 时写死两笔——`callname:id:-1` = 角色预设的**名前**，`callname:id:-2` = 预设的**呼び名**（缺省回落到名前）；`callname:c:u`（c 对 u 的称呼）未设定时，回落取的是 u 的 `-2`。两者在多数预设角色身上取值相同，**写反了测试也看不出来**（#44 与 #50 并发时各写各的、双方用例都测不出，事后靠引擎源码定案）。另注意本作把 `SAVESTR:x` 赋成 `%NAME:x%`，所以它等价于名前、不是呼び名。

**`FLAG` 的保留区**：Emuera 有几个内置标量（日期、时段、持有金、角色指针）在引擎里没有对应表，按决议并入 `flag`，占用一段高位序号。它们在本项目里仍用各自的中文名（日期、所持金…），不叫「旗标」。

## 流程与机制

| 本项目用词 | 原作                         | 引擎             | 说明                                                  |
| ---------- | ---------------------------- | ---------------- | ----------------------------------------------------- |
| 转场       | `BEGIN`                      | 无对应，移植自建 | 切换游戏阶段。**不是立即跳转**，详见下                |
| 转场信号   | —                            | 移植自建         | `BEGIN` 的 JS 载体，用异常实现「结束当前函数」        |
| 游戏状态   | `BEGIN` 的目标关键字         | 移植自建         | 标题、新游戏、据点、调教、调教后、回合结束            |
| 事件链     | 同名函数的多处定义           | 移植自建         | 一个事件挂多个处理器，全部执行，分三档优先级          |
| 分发族     | `TRYCALLFORM` 的同前缀函数群 | 移植自建         | 按编号命中唯一实现的查表机制                          |
| 口上       | `口上` / `EVENT_K*`          | —                | 角色台词与反应的状态机，占原作近一半体量              |
| 调教       | `調教`                       | —                | 核心玩法循环                                          |
| 据点       | `SHOP`                       | —                | 主菜单所在的枢纽画面。原作函数名叫 shop，但它不是商店 |
| 回合结束   | `TURNEND`                    | —                | 日期推进与结算                                        |

**「据点」与「商店」要分清**：原作的 `@EVENTSHOP` / `@SHOW_SHOP` / `@USERSHOP` 是**主菜单**，购物只是它的一个入口（另有独立的道具商店函数）。本项目里「据点」指主菜单画面，「商店」专指买卖道具。

## 架构术语

决议见 `docs/adr/`。这些词是移植版自建的，原作与引擎都没有对应物。

| 用词       | 含义                                                                                                                                                                                                                                                                                    |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 域         | 玩法维度的所有权单元：口上 / 调教 / 角色 / 据点 / 迷宫 / 侵略 / 事件 / 系统。一个域拥有若干变量区段；清单是产物里的一张表，不是硬编码枚举                                                                                                                                               |
| 门面       | 变量访问的入口，按域分组且一维二维对称：`chara(cid).<域>.<字段>` 与 `game.<域>.<字段>`。生成的 class，无 Proxy；字段名用中文（对得上 ERB）；`chara(cid)` 按角色 ID 缓存单例视图。既有扁平 `era_flag` / `era_global` 并存；一维重切不强制迁移，口上域两个样本（#71）已迁，其余随子系统票 |
| 区段所有权 | 「某段变量下标归某个域」的映射。由离线脚本从 `target/` 实测导出，非人工划定                                                                                                                                                                                                             |
| 跨域写     | 一个域写入另一个域拥有的区段。允许，但必须经属主域导出的具名方法；**跨域读不受限**                                                                                                                                                                                                      |
| 画面组件   | 表现层的单元，知道自己占几行（绘制前后 `getLineCount()` 的差值）                                                                                                                                                                                                                        |
| 重绘       | 组件清掉自己占的行并重画（`clear(自己的行数)` + 重画）。**只发生在玩家交互之后**——叙述流中间重绘会打断玩家的右键快进                                                                                                                                                                    |
| 两相       | 每张票**内部**的两个阶段：1:1 移植（过对拍与测试）→ 当场重构进目标架构。不是项目级的先后                                                                                                                                                                                                |
| 引擎事实   | 引擎对我们给的参数做的一次变换，且**夹具的记录行为真的依赖它**（如 `barWidth` 缺省 24 会让条后文字整列不渲染）。事实进表，同时喂给锚点校核（守引擎变没变）与调用点规则（守我们踩没踩上）；喂不动的是叙述，不是事实。可达性分三层，见 ADR-0005                                           |

**「行（Row）」是引擎的编程行，不是显示行。** 一次 `printMultiColumns` 无论输出几个格子都只占一个 Row，`clear(1)` 会把它们一起清除；而一段长文本自然换行成三个显示行时仍只是一个 Row。画面组件的行数指的是 Row 数。

## 三条容易误解的语义

**转场不是立即跳转。** 发出转场后，当前函数立刻结束，但事件链**继续跑完剩余的处理器**；期间若再次发出，后者覆盖前者，最后一个胜出；整条链退出后才真正切换状态。按「立即跳转」实现会静默跳过大段结算逻辑。

**未声明的变量序号，行为不统一——但判据不是「几段寻址」。** 真正决定行为的是两件事的组合：该表的**名字表**（`yml/` 里的静态表）在不在、该角色的 **data 桶**在不在。名字表在且桶在 → 写入成功，未声明的下标回落成数字本身（这就是「静默创建」）；名字表在但桶不在 → 静默丢弃；**名字表不在而桶在 → 直接抛错**，二段与三段一样（`flag:*` 之所以静默通过，只是因为 `Flag.yml` 在）。「别的表这么写没事」推不出「这张表也没事」。

**「已加入序号」与「角色 ID」在原作里常常重合，但不等价。** 原作按加入顺序连续编号，故两者在原作语境下可互换；ere 侧一律用角色 ID，因此原作里形如「编号大于总数即越界」的判据不能照抄，须按语义改写为「不在已加入列表中」。
