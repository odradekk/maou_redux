本章主要介绍存读档系统及界面的实现，主要用到 [era.saveData、era.loadData、era.rmData 和 era.resetData 等 API](./11-saves) 和 [global 表](./09-static#globalcsv-与-global-表) 等数据结构。

# 前置页面

存读档系统是游戏中的常见重要系统，其中存档界面的入口一般在游戏的主界面（开始新游戏或读取存档之后的界面），读档的入口则在游戏的主界面和标题界面。在实现存读档系统之前，需要先实现它们的入口，不然测试无从谈起。标题界面已经在 [#6 输出](./06-output#标题界面的实现) 一章中实现，因此本节主要介绍一个简单主界面的实现。

为妥善组织游戏脚本文件，笔者一般在ere文件夹下创建data、page、system等文件夹，data文件夹用于放置常量数据文件，page文件夹放置界面脚本，system文件夹放置与界面绘制无关的系统功能脚本。之后，在page文件夹下创建homepage.js文件，然后输入以下内容：

```javascript
// #/page/homepage.js
const era = require('#/era-electron');

async function homepage() {
  let flag = true;
  while (flag) {
    await era.clear();
    era.drawLine({ content: '游戏主界面' });
    era.printMultiColumns(
      ['保存进度', '加载存档', '标题界面'].map((e, i) => ({
        accelerator: i + 1,
        config: { align: 'center', width: 8 },
        content: e,
        type: 'button',
      })),
    );
    switch (await era.input()) {
      case 3:
        flag = false;
    }
  }
}

module.exports = homepage;
```

这个文件导出了一个名为 homepage 的函数，其中有一个交互循环，绘制了一个带有文本的分割线以及三个按钮，选择第三个按钮【标题界面】会返回到标题界面。这就是一个简易的游戏主界面。然后，还需要让标题界面可以跳转到它：

```javascript
// #/main.js
const era = require('#/era-electron');

const homepage = require('#/page/homepage');

module.exports = async () => {
  let flag = true;
  while (flag) {
    await era.clear();
    era.setAlign('center');
    era.drawLine({ isSolid: true });
    era.print('我是一个游戏标题');
    era.print(`v${era.get('gamebase').version / 1000}`);
    era.print('你');
    era.drawLine({ isSolid: true });
    era.printButton('开始游戏', 1);
    era.printButton('加载存档', 2);
    era.printButton('鸣谢列表', 3);
    era.drawLine({ isSolid: true });
    era.setAlign('left');
    let copyright_flag, curr_line;
    switch (await era.input()) {
      case 1:
        // 点击【开始游戏】时，重置当前存档并进入 homepage
        era.resetData();
        await homepage();
        break;
      case 3:
        copyright_flag = true;
        curr_line = era.getLineCount();
        while (copyright_flag) {
          era.setAlign('center');
          era.printButton('开发人员', 1);
          era.printButton('口上作者', 2);
          era.printButton('社区维护', 3);
          era.printButton('回到标题', 4);
          era.setAlign('left');
          const ret = await era.input();
          era.setAlign('center');
          switch (ret) {
            case 1:
              await era.printAndWait('这里是开发人员列表');
              await era.printAndWait('这里是开发人员列表2');
              break;
            case 2:
              await era.printAndWait('这里是口上作者列表');
              break;
            case 3:
              await era.printAndWait('这里是社区维护列表');
              break;
            case 4:
              copyright_flag = false;
          }
          if (ret < 4) {
            await era.clear(era.getLineCount() - curr_line);
          }
          era.setAlign('left');
        }
    }
  }
};
```

上面的代码是对第六章 [带子界面的标题界面](./06-output#子界面) 的代码进行微调的结果，主要改动点在于读取按钮输入后的判断 if 修改为了 switch，子界面的交互循环放在 `case 3:` 下面，然后在 `case 1:` 下面调用 era.resetData 重置当前存档后调用从 `#/page/homepage.js` 导入的函数，就可以进入游戏主界面的交互循环：

# 存档系统

要想读档，需要先有存档可以读，因此笔者会先实现存档系统。首先是设计：存档系统应该列出一些可用的栏位，显示为按钮，并在点击后触发存档行为；每个存档最好有个独立按钮，点击后触发存档名的修改行为；最后，需要一个按钮返回到游戏主界面。

## 存档

首先先实现存档栏位和存档行为。创建新文件`#/page/page-save-game.js`，输入以下内容：

```javascript
// #/page/page-save-game.js
const era = require('#/era-electron');

async function page_save_game() {
  let flag = true;
  while (flag) {
    await era.clear();
    const buffer = [];
    buffer.push({ config: { content: '保存游戏' }, type: 'divider' });
    // 绘制存档栏位
    buffer.push(
      { type: 'divider' },
      {
        accelerator: 999,
        config: { align: 'right' },
        content: '返回',
        type: 'button',
      },
    );
    era.printMultiColumns(buffer);
    const ret = await era.input();
    if (ret === 999) {
      flag = false;
    }
  }
}

module.exports = page_save_game;
```

这样就创建了一个空的存档界面，现在只有一个快捷键为999的按钮，点击后退出交互循环。按钮上方有两条分割线，其中就是需要放置存档栏位按钮的部分。

根据之前 [对特定存档的介绍](./11-saves#概览-1)，save0.sav也就是0号栏位的存档一般用于自动存档，因此存档栏位按钮应该是一批快捷键从1开始、具有连续快捷键的按钮，每个一行；特定栏位存档的备注被保存在 [global 表的 saves 对象属性](./11-saves#概览) 中，可以使用 ``era.get(`global:saves:${存档栏位}`)`` 获取。于是有以下代码：

```javascript
// #/page/page-save-game.js
// ...
// 绘制有【保存游戏】文本的分割线
for (let i = 1; i <= 10; ++i) {
  const comment = era.get(`global:saves:${i}`);
  buffer.push({
    accelerator: i,
    content: comment || '空栏位',
    type: 'button',
  });
}
// 绘制分割线
// ...
```

上面的代码扫描1到10栏位的存档备注，然后将备注作为按钮的文本。如果备注是空的（`undefined`），就显示为【空栏位】。然后为点击栏位绑定动作：

```javascript
// #/page/page-save-game.js
// ...
if (ret === 999) {
  flag = false;
} else {
  await era.saveData(ret, '存档 ' + ret);
}
// ...
```

这样在点击按钮后就会将当前存档保存到存档文件中，并设置备注为 `` `存档 ${存档栏位}` ``。现在将存档界面绑定到游戏主界面的按钮上：

```javascript
// #/page/homepage.js
const era = require('#/era-electron');

const page_save_game = require('#/page/page-save-game');
// ...
    switch (await era.input()) {
      case 1:
        await page_save_game();
        break;
      case 3:
        flag = false;
    }
// ...
```

然后在引擎中重载游戏，进入存档界面：

![存档界面](../imgs/76-存档界面.png)

一般游戏在保存到非空存档时有覆盖提醒功能，可以在`#/page/page-save-game.js`通过存档备注检查存档是否非空（备注是`undefined`或者以 [`(FILE LOST) `](./11-saves#eraloadglobal读取公共存档) 开头），即在存档按钮绑定的动作中增加一组按钮和输入即可：

```javascript
// #/page/page-save-game.js
// ...
const comment = era.get(`global:saves:${ret}`);
if (comment !== undefined && !comment.startsWith('(FILE LOST) ')) {
  era.print('该栏位已存在存档！是否覆盖？');
  era.printButton('是', 1);
  era.printButton('否', 2);
  if ((await era.input()) === 2) {
    continue;
  }
}
await era.saveData(ret, '存档 ' + ret);
// ...
```

## 修改存档名

修改存档名按钮一般会出现在栏位按钮右侧，点击后触发一个输入框，然后以输入文本作为该栏位存档新的备注。这个行为有两个限制，一是不应该允许修改不存在存档文件的栏位的存档名，二是存档备注应该存在长度上的限制。

第一个限制可以通过在添加按钮时设置config.disabled实现：

```javascript
// #/page/page-save-game.js
// ...
buffer.push(
  {
    accelerator: i,
    config: { width: 20 },
    content: comment || '空栏位',
    type: 'button',
  },
  {
    accelerator: i + 100,
    config: {
      align: 'right',
      disabled:
        comment === undefined || comment.startsWith('(FILE LOST) '),
      width: 4,
    },
    content: '改名',
    type: 'button',
  },
);
// ...
```

而第二个限制则需要在绑定的动作里实现：

```javascript
// #/page/page-save-game.js
// ...
// 判断是否是对存档的改名操作
} else if (ret > 100) {
  const savIndex = ret - 100;
  let comment;
  const cur_line = era.getLineCount();
  do {
    await era.clear(era.getLineCount() - cur_line);
    era.print('请输入新存档名（不超过10个字符）');
    comment = (await era.input()).toString();
    // 检查comment的长度是否超出10个字符
  } while (comment.length > 10);
  era.set(`global:saves:${savIndex}`, comment);
  // 保存通用公共存档到global.sav
  await era.saveGlobal();
} else {
// ...
```

上面这段代码有三个关键点：

* 改名按钮的快捷键均大于100，所以通过检查快捷键是否大于100来进入改名分支；
* 限制要求是存档名不超过10个字符，所以超过10个字符时需要回到循环中重新输入；
* 因为没有调用 era.saveData，所以在修改 global 表的内容后需要使用 era.saveGlobal 手动将改动写回。

# 读档系统

与存档系统类似，读档系统也应列出一系列按钮形式的存档栏位，有存档文件的点击后读档，没有的就禁用该按钮；每个栏位有一个额外的独立按钮，点击后删除该存档；最后，需要一个按钮返回游戏主界面。

## 读档

创建新文件`#/page/page-load-game.js`，输入以下内容：

```javascript
// #/page/page-load-game.js
const era = require('#/era-electron');

async function page_load_game() {
  let flag = true;
  while (flag) {
    await era.clear();
    const buffer = [];
    buffer.push({ config: { content: '读取游戏' }, type: 'divider' });
    for (let i = 0; i <= 10; ++i) {
      const comment = era.get(`global:saves:${i}`);
      buffer.push({
        accelerator: i,
        config: {
          disabled: comment === undefined || comment.startsWith('(FILE LOST) '),
        },
        content: comment || '空栏位',
        type: 'button',
      });
    }
    buffer.push(
      { type: 'divider' },
      {
        accelerator: 999,
        config: { align: 'right' },
        content: '返回',
        type: 'button',
      },
    );
    era.printMultiColumns(buffer);
    const ret = await era.input();
    if (ret === 999) {
      flag = false;
    } else if (await era.loadData(ret)) {
      // 这里可以插入对旧版本存档的修复
      // 只有在读档成功的情况下才返回
      return true;
    }
  }
  // 通过返回值告诉入口的交互逻辑是否读档成功
  return false;
}

module.exports = page_load_game;
```

关键点有两个，一个是利用了 era.loadData 的返回值，另一个就是通过 page_load_game 本身的返回值通知入口处的交互逻辑是否读档成功，这主要在 `#/main.js` 中有用。

可以看到 `#/page/page-load-game.js` 的结构与实现基本存档功能后的 [`#/page/page-save-game.js`](#存档) 类似，这种基本的界面框架属于构造游戏界面风格的一部分，笔者将会在后面的章节中经常使用。

读档系统有两个入口，标题界面和游戏主界面，修改相应的入口代码即可：

```javascript
// #/main.js
// ...
case 2:
  if (await page_load_game()) {
    await homepage();
  }
  break;
// ...
```

```javascript
// #/page/homepage.js
// ...
case 2:
  await page_load_game();
  break;
// ...
```

可以看到，`#/main.js` 利用了 page_load_game 的返回值，仅在读档成功的情况下会进入游戏主界面，其他情况下则继续交互循环。

## 删除存档

删除存档功能应该在存在存档文件时有效，也就是说删除存档按钮的 config.disabled 应该与存档栏位按钮的相同。但如果存档有 `(FILE LOST) ` 前缀，则表明这个存档栏位是无效的，也应该允许玩家清除这样的存档。综合以上条件，对 `#/page/page-load-game.js` 进行以下改造：

# 小结

本章介绍了存读档系统的实现，利用了 [特定存档相关的 API](./11-saves#专属的特定存档-savesav)、[era.saveGlobal](./11-saves#erasaveglobal保存公共存档) 和特定存档备注的相关细节，在基本的存读档功能之外实现了存档改名和读档删除功能。

本章还实现了一个简单的 [游戏主界面](#前置页面)，它会作为其他游戏系统和内容的主要入口在「参考实现篇」的其他章节中继续沿用。
