_PC引擎4.0.0、安卓引擎1.0.9及以上版本_

_分割线设置、颜色字典化配置需要PC引擎4.0.1及以上版本_

_按钮注释需要PC引擎4.1.0及以上版本_

_条件闭包需要PC引擎4.1.1及以上版本_

.kojo 口上文件是一种基于 YAML 语法的口上格式，致力于提供一种面向 EraElectron 与 ere.app 引擎的、比 JavaScript 门槛更低的口上富文本写作与录入格式。借助 .kojo，ere 游戏的创作者们可以：

* 口上作者可以专注文本的显示效果与内容逻辑，而无需学习或考虑 JavaScript 代码实现的具体细节；
* 开发者可以专注事件的触发逻辑和奖惩效果，而无需将口上文本翻译为可执行的 JavaScript 代码。

写好的 .kojo 口上文件可以使用 [Kojo 文件测试](https://gitgud.io/umaera/game/kojo-test) 项目进行有效性和显示效果测试。

# 创作 .kojo（面向口上作者）

口上作者可以先在 .yml 文件中按照本节所述的内容创作口上，然后再改回 .kojo 后缀名使用。

## 语法

* .kojo 文件的后缀为 .kojo，例如 `red.kojo`；
* .kojo 是大小写敏感的；
* .kojo 文件必须是 UTF-8 或 UTF-8 BOM 编码；
* 使用缩进表示层级关系，但不允许使用 tab，必须是半角空格（` `）；
* 空格的数量不重要，相同层级的元素左对齐即可；
* `#` 号表示注释，后面的内容会被引擎无视；
* `:` 号和 `-` 号后面要加空格；
* 每个句子开头和结尾的空格（` `）会被无视，如果开头和结尾的空格有实际含义，使用半角引号（`'`或`"`）包起来（但不要和句子中本身就有的引号重复）；
* 句首的 `#` 号会导致这个句子被引擎无视，此时也请使用半角引号包住整个句子。

## 基本用法

.kojo 文件内容以篇目为基本单位，每篇文本都需要一个名字，然后引擎通过名字执行口上并输出相应的文本。同一个 .kojo 文件中不同篇目的名字不能相同。

```yaml
# base1.kojo
冬天:
- 过了数日，已是寒风凛冽的时候。
- 被天气剥夺了出行权的瓦来只能在床上坐起，呆呆地从窗口窥探外面的世界。

夏天:
- 似乎离那些花谢了没多久，树上的蝉就鼓噪起来了。
- 瓦来从卧室搬了出来，躺在小隔间的凉席上，然后将卧室和客厅正对着的窗户大大地打开，试图从偶尔吹过的过堂风中获得一丝凉爽。
- 似乎是在庆祝主人又成功挺过了严寒的冬日和微冷的春天，客厅摆放的植物们都青青翠翠的，在明媚的阳光中恣意生长。
```

上面的 .kojo 文件中定义了两个篇目，每个篇目名称后输入半角冒号（`:`）并换行，其对应的文本分行写在之后，每行以一个半角破折号（`-`）开头，注意半角破折号后需要跟一个半角空格。

篇目和篇目对应的文本行组成了 .kojo 文件的基本结构。引擎在执行这样的篇目时会分行显示文本，并在显示一行文本后等待玩家按任意键才会继续显示下一行。

> 也就是说，引擎以每行文本作为参数调用了 [era.printAndWait](./05-interaction#eraprintandwait杂交版)。

如果要显示空行，可以输入单独成行的半角破折号：

```yaml
# base2.kojo
你好:
- 你好？
-
- 世界！
```

引擎执行篇目【你好】时，在「你好？」和「世界！」之间会显示一个空格，这个空格会和「世界！」一同显示。

> 引擎显示空行时使用了 [era.println](./06-output#eraprintln)。

```yaml
# base3.kojo
分割线:
- divider: true
- 上面是一个分割线
```

在执行上面的口上时，引擎会显示一条分割线和一行文本「上面是一个分割线」。注意半角冒号后需要跟一个半角空格。

## 按钮与分支

如果要显示按钮，需要输入按钮的快捷键值和按钮内容：

```yaml
# button1.kojo
按钮:
- 下面是一个按钮：
-
- acc: 0
  content: 一个按钮
-
- 你看到一个按钮了吗？
```

在执行时，玩家需要手动点击按钮才会显示空行和「你看到一个按钮了吗？」。

> 如果玩家点击右键进行快进，这样的单个按钮会被跳过，直接快进到「你看到一个按钮了吗？」显示之后。

相邻的多个按钮可以组成按钮组：

```yaml
# button2.kojo
按钮组:
- 下面是一个按钮组：
-
- acc: 0
  content: 一号按钮
- acc: 1
  content: 二号按钮
-
- 点击任意一个按钮才能看见我
```

在执行时，这两个按钮会被显示在不同的行，玩家需要手动点击两个按钮之一才会显示空行和「点击任意一个按钮才能看见我」。

如果口上中需要针对玩家选择的按钮显示不同文本，随后显示相同内容，可以通过按钮组控制分支：

```yaml
# button3.kojo
分支:
- 下面是一个带内容分支的按钮组：
-
- acc: 0
  content: 一号按钮
  lines:
  - 你点击了一号按钮
  - Good idea!
- acc: 1
  content: 二号按钮
  lines:
  - 你点击了二号按钮
  - Very nice!
-
- 点击任意一个按钮才能看见我
```

在执行时，点击一号按钮后会显示「你点击了一号按钮」「Good idea!」两行文本，点击二号按钮后会显示「你点击了二号按钮」「Very nice!」两行文本。无论选择哪个按钮，最后都会显示空行和「点击任意一个按钮才能看见我」。

按钮的内容分支中的口上文本结构需要符合 [基本用法](#基本用法)（当然，缩进得控制在 `lines:` 这一行之后）。

（_需要PC引擎4.1.0及以上版本_）引擎中的按钮文字不会自动换行，如果按钮的文本过长之时可能需要在按钮之后单独输出一行文字，此时可以通过 comment 字段为按钮增加紧跟的单行文本注释：

```yaml
# button4.kojo
按钮注释:
- 下面是一个带单行注释的按钮组：
-
- acc: 1
  content: 一号按钮
  comment: 这是一号按钮，点击后什么都不会发生。
- acc: 2
  content: 二号按钮
  comment: 这是二号按钮，点击后会输出一行文字。
  lines:
  - 你点击了二号按钮！
```

在执行时，两个按钮的下方都会出现单独一行文字，用于点击按钮的含义与后果的辅助说明。

（_需要PC引擎4.1.0及以上版本_）同一按钮组中的按钮的快捷键可以重复，引擎在加载 .kojo 文件时会自动解决重复问题，但仍然建议口上作者仔细检查并尽量避免同一按钮组中按钮快捷键的重复，以避免获取关键选择肢时判断错误。

## 随机文本

有些时候作者可能希望游戏在可选的内容中随机选择一项显示，而非死板的固定内容，这种做法在日常口上中最为常见，此时可以将所有可选内容以以下格式组织：

```yaml
# random1.kojo
随机文本:
- random: true
  lines:
  - 你随机到了我！
- random: true
  lines:
  - 你真幸运！
```

在执行时，引擎将随机显示「你随机到了我！」「你真幸运！」其中的一句。

可以注意到随机文本的关键词是 lines，意味着可以在多组多行文本之间随机：

```yaml
# random2.kojo
随机多行文本:
- random: true
  lines:
  - 你随机到了我！
  - 你真幸运！
- random: true
  lines:
  - 哇我真幸运！
  - 我随机到了你！
  - 太棒了！
```

在执行上面的口上时，引擎将随机显示其中的一组文本，并且每显示一行文本就会等待一次玩家输入。

## 文本嵌套

按钮分支和随机文本都以 lines 关键词定义，需要符合 [基本用法](#基本用法)，这意味着按钮分支和随机文本可以相互嵌套：

```yaml
# embedding.kojo
嵌套:
- 这里是一个千层饼
-
- 我在第几层？
-
- acc: 0
  content: 第一层！
  lines:
  - 那你是看到了第二层
  -
  - acc: 0
    content: 所以呢？
    lines:
    - random: true
      lines:
      - 你只把我想成了第一层
      -
      - acc: 0
        content: 不然呢？
        lines:
        - 其实，我在第五层
    - random: true
      lines:
      - 实际上，我是第五层
- acc: 1
  content: 第五层！
  lines:
  - 聪明，bro，聪明！
```

引擎在执行/随机到相应分支后，会继续按照分支定义的文本/按钮分支/随机文本显示相关内容。

## 动态指定

有些时候，口上需要用到运行游戏时才能确定的变量，比如玩家的名字、玩家的称呼、当前参与事件的角色的性别、甚至玩家的性经历等等。.kojo 可以通过字典来声明并在执行时动态指定这些内容。

字典（dictionary）在编程中是一种重要的映射类数据结构，用于存储键值对。在 .kojo 动态指定中，字典用于存储需要动态指定的关键词和在执行时会动态替换成的内容的映射关系，例如下面这个数据结构：

```json
{
  "玩家名": "你先生",
  "玩家称呼": "你"
}
```

.kojo 主要支持三种显示内容的动态指定：普通文本、按钮文本和 [颜色](#富文本效果)（_需要PC引擎4.0.1及以上版本_）。如果一个关键词需要在执行时动态指定内容，需要在 .kojo 文件中用`%`包起来，例如：

```yaml
# dictionary.kojo
动态指定:
- %玩家称呼%好，%玩家名%！
```

在执行上面的口上时，如果给定的字典是上面的例子，则会输出一行文本「你好，你先生！」。按钮文本内容的动态指定方法类似。

## 条件显示

大部分显示内容都可以通过增加 if 关键词使其变为需要满足条件后才能显示：

```yaml
# if.kojo
条件显示:
- divider: true
  if: 2 > 1
- acc: 0
  if: 3 > 2
  content: 条件按钮
- if: Math.random() < 0.5
  content: 我有一半的概率显示，因为 Math.random() 会返回 [0,1) 之间的随机小数
- if: 3 > 4
  lineUp: true
- random: true
  if: era.get('version') > 0
  lines:
  - 随机显示的内容一直会是我，因为只有我的条件检查是可以通过的
- random: true
  if: era.get('version') === undefined
  lines:
  - 随机显示的内容永远不是我，因为我的条件检查是永远不会通过的
```

上面定义的口上中所有显示内容都需要经过条件检查，只有条件检查通过的内容才会被显示，其中有三个注意点：

* 文本内容需要经过变形才能设置条件，即作为 content 关键词对应的内容；
* 空行也需要经过变形才能设置条件，即转变为 `lineUp: true`；
* 随机文本设置条件之后，在执行时会先进行条件检查，然后在条件检查的结果中随机。
  * （_需要PC引擎4.1.1及以上版本_）如果所有内容的条件检查都没有通过，则会默认所有条件检查均为通过，即在所有内容中随机。例如上面的例子中，如果 `era.get('version')` 的结果是 `-1`，两种随机文本的条件检查均为不通过，则会随机显示「随机显示的内容一直会是我，因为只有我的条件检查是可以通过的」或「随机显示的内容永远不是我，因为我的条件检查是永远不会通过的」。

条件的内容是 JavaScript 代码，只能使用以下内容：

* JavaScript 默认的同步运算符和数据类型；
* JavaScript 内置的 Math 对象的属性函数（取随机数的 Math.random、上取整的 Math.ceil、下取整的 Math.floor 等）；
* EraElectron 引擎 SDK 的同步函数（以变量 era 的属性取用，例如 era.get 等）；
* 动态指定的字典（以变量 d 取用）；
* 玩家选择的按钮快捷键的数组（以变量 a 取用）。

> 如果口上作者无法以 JavaScript 代码给定条件或者觉得麻烦，请在 .kojo 中以`#`开头的注释形式说明你的需求，然后联系相应的游戏开发者。

（_需要PC引擎4.1.1及以上版本_）如果希望用一个条件控制多行文本的显示，可以使用 **条件闭包** 功能：

```yaml
# if2.kojo
条件闭包:
- if: Math.random() < 0.5
  lines:
  - 我们有 50% 的概率，
  - 会显示出来。
  - 如果没有通过概率判定，
  - 这里只会是一片空白。
```

## 富文本效果

.kojo 支持对文本和分割线（_需要PC引擎4.0.1及以上版本_）的富文本效果进行设置，设置选项来自于 [era.print](./06-output#eraprint) 和 [era.drawLine](./06-output#eradrawline) 的相应参数的属性。

> 可以查看 API 文档中的 [TextConfig](./A-api-docs#textconfig) 和 [DividerConfig](./A-api-docs#dividerconfig)。

下面的例子中展示了一些常用的设置选项：

```yaml
# text1.kojo
富文本:
- content: 一行红色放大的文本
  color: red # 可以使用颜色的英文名，以#开头的十六进制的颜色，或者rgb(x,y,z)这样以RGB定义的颜色
  fontSize: 1.5rem # 将这行文本的字体尺寸为游戏设置的1.5倍，默认设置下将是16*1.5=24 (px)
  align: center # 将这行文本居中显示，设置为 right 会右对齐
# 对分割线的设置需要PC引擎4.0.1及以上版本
- divider: true
  content: 分割线上显示的文本
  position: left # 这会使文本显示在分割线左侧，如果设置为 right 会显示在右侧
```

在变形化后的文本内容中，可以进一步分别设置每段文本的富文本效果，例如：

```yaml
# test2.kojo
分段设置富文本:
- content:
  - 这行文本个个都身怀绝技：
  - color: red
    content: 有染红的，
  - fontSize: 1.5rem
    content: 有变大的，
  - fontWeight: bold
    content: 有变粗的，
  - fontStyle: italic
    content: 有变斜的，
  - title: 我是小提示
    content: 有会显示小提示的，
  - content: 还有什么都不会的
```

这些设置可以拆分组合，以满足显示效果的需要。

> 对应 [era.print](./06-output#eraprint) 的对象数组模式。

（_需要PC引擎4.0.1及以上版本_）对 **整行文本** 的颜色设置可以通过字典动态指定，例如：

```yaml
# test3.kojo
动态指定颜色的文本:
- content: 猜猜我是什么颜色？
  color: %COLOR%
```

在执行时「猜猜我是什么颜色？」的颜色将根据字典中关键词`COLOR`对应的字符串值动态指定。

注意 **分段文本的颜色无法通过字典动态指定**。

## 同时显示文本

以上介绍的 .kojo 使用方法执行效果都是每显示一行文本都要等待玩家按任意键才继续显示下一行。如果需要使这些内容同时输出，需要在口上定义中使用 sync 关键词，即：

```yaml
# sync.kojo
同时显示的文本:
  sync: true
  lines:
  - 我和下面一行文本会同时显示
  - 我和上下两行文本会同时显示
  - 我们不需要玩家按任意键才继续显示
```

在设置 sync 关键词的情况下，[随机文本](#随机文本)、[动态指定](#动态指定)、[条件显示](#条件显示) 和 [富文本效果](#富文本效果) 都是有效的，但 [按钮与分支](#按钮与分支) 将无效化，也不能在随机文本中嵌套使用按钮分支。

# 执行 .kojo（面向开发者）

## 使用示例

在口上作者写好 .kojo 文件后，开发者可以通过 require 方法将其引入到游戏脚本中：

```javascript
// 普通引入
const base1_kojo = require('#/base1.kojo');

// 或者解构赋值语法
const { '冬天': winter } = require('#/base1.kojo')
```

需要注意 .kojo 文件的加载 **不能在 SDK 加载之前**。

> 可以通过在 main.js 首行就完成 SDK 的加载来解决。

然后就可以以函数形态执行口上了：

```javascript
// ...
const base1_kojo = require('#/base1.kojo');
await base1_kojo['春天']();
// ...
```

其中，只有同时显示文本的口上可以作为同步函数使用，其他口上都必须以异步函数形态使用：

```javascript
// ...
const { '你好': hello } = require('#/base2.kojo');
await hello();
// ...
const sync_kojo = require('#/sync.kojo');
sync_kojo['同时显示的文本']();
// ...
```

如果口上文本中有需要动态指定的关键词，则需要以字典对象作为参数：

```javascript
// ...
const dict = JSON.parse('{"玩家名":"你先生","玩家称呼":"你"}');
const dict_kojo = require('#/dictionary.kojo');
await dict_kojo['动态指定'](dict);
```

异步函数的情况（即并非需要同时显示的文本）下，口上函数会输出一个数组，其中以玩家的点击顺序排列了所有玩家选择的按钮的快捷键值，用于根据玩家选择触发相应逻辑或修改相应变量。

## 生成 Android 版

要打包 .kojo 文件，需要为 webpack 配置专门的 loader：[kojo-loader](https://gitgud.io/umaera/engine/kojo-loader)。

打开命令行工具，打开到游戏项目文件夹，输入以下指令：

```shell
npm install -D git+https://gitgud.io/umaera/engine/kojo-loader.git
```

然后修改 webpack.config.js：

```shell
// webpack.config.js
// ...
module.exports = {
  // ...
  module: {
    rules: [
      // ...
      {
        test: /\.kojo$/,
        use: [
          {
            loader: require.resolve('kojo-loader'),
            options: {
              sdkPath: '#/era-electron',
            },
          },
        ],
      },
    ],
  },
  // ...
};
```
> 上面的代码指定了 .kojo 文件的加载器，这样在加载 .kojo 文件时会自动转换为可执行的 JavaScript 代码，达成将 .kojo 文件打包到安卓游戏包中的目的。
>
> 如果 SDK 经过改名或修改过位置，可以修改上面配置中 sdkPath 对应的字符串值为 SDK 的对应路径（以`#`开头）。

修改配置后，就可以通过 `npm run webpack` 或 `npx webpack` 将 .kojo 文件打包进安卓游戏包了。
