# 静态数据文件

静态数据文件是指csv文件夹下的CSV文件，定义了游戏的信息、游戏存档中使用的变量名和预定义的角色数据等，主要分为游戏信息表、变量数据表和角色数据表三类。

CSV（Comma-Separated Values，逗号分隔值）文件是一种存储表格和电子表格信息的纯文本文件，其内容通常是一个文本、数字或日期的表格。[^1] CSV文件中以换行分行，一般以半角逗号`,`为分隔符分隔行中的列。因此每个CSV文件都可以称为一个表。

[^1]: [什么是 CSV 文件，如何打开 CSV 文件格式](https://www.freecodecamp.org/chinese/news/what-is-a-csv-file-and-how-to-open-the-csv-file-format/)

注意所有CSV文件都应该是UTF-8或UTF-8-BOM编码保存，且以半角逗号`,`为分隔符。

此外，CSV文件中也可以使用注释，注释内容以`;`开头。

EraElectron对静态数据会自动进行大小写转换，以下提到的任意表名和变量名都可以包含任意大小写的字母，引擎会将大小写不同的字母识别为相同的字母。放置这些文件的文件夹也同理，可以是csv或CSV或任意大小写形态。

> 例如，GameBase.csv 和 gamebase.csv 都会被识别为游戏信息表。在使用时，`flag:0`、`Flag:0`和`FLAG:0`都会被识别为 flag 表中序号为0的变量的取值。

## 变量数据表

变量数据表是CSV文件夹下的其他CSV文件，用于定义存档数据中的数据表和数据表中的变量。在游戏中可以用这些定义的变量名控制存档数据中的相应变量，存档数据在存档之后会保存到存档文件中。这些变量是游戏开发过程中需要操作的主要对象。

> 在 emuera 中，数据表中的变量取值有严格的规定，而且需要预先声明数据表中的变量数量的限制。在EraElectron中因为 JavaScript 泛型的优势，这些限制均被解除，可以任意给变量赋值 **JavaScript 允许的任意变量类型**。但在初始化时，这些数据表中的变量仍然会被赋值为 `0`（cstr表会被赋值为空字符串`''`）。

变量数据表一般分为两列：第一列为变量序号，Number 类型；第二列为变量名，String 类型。变量序号和变量名**不能重复**，任意变量名也**不能与变量序号相同**。

> 虽然实际上**并非不能重复**，但是重复可能导致一些无法预期的后果：\
> EraElectron引擎在变量数据表的读取上有一定的容错性，当变量序号重复时，引擎会从给定的变量序号开始逐渐+1直到找到一个没有被使用的变量序号为止，然后作为该变量的序号；也就是说，会自动生成一个变量序号。因为是自动生成的，在CSV文件修改后，生成的变量序号可能被新的变量所占用，此时之前使用生成的变量序号的变量会具有新的变量序号，从而导致存档数据含义变更，无法和之前兼容。\
> 变量名重复则会按照最后定义的变量序号作为该变量名的序号，但之前的序号仍然被该变量名占用，变量数据表初始化后两个序号都会有对应的初始化值但只有后者被实际使用，从而导致存档数据空间的浪费。

注意变量数据表文件**不能放到csv文件夹的子文件夹中**。

### 一维表：系统变量

一维表是指对应的数据表是一维的，即基本结构为`变量名:变量取值`这样的变量对，操作变量时通过`表名:变量名` 指定目标变量。一维表一般用于存储与角色无关的系统变量。

#### Flag.csv 与 flag 表

Flag.csv 与 flag 表对应，该表也可称为系统旗标表，用于定义和保存一些系统级的变量。该表属于特定存档的一部分，会被保存到存档文件中。

flag 表的具体用法：

* `` `flag:${变量名}` ``：变量名对应的旗标变量的值；
* `` `flag:${变量序号}` ``：变量序号对应的旗标变量的值；
* `` `flagname:${变量序号}` ``：变量序号对应的旗标变量名；
* `'flagnames'`：所有旗标变量的变量名按定义顺序组成的数组；
* `'flagkeys'`：所有旗标变量的变量序号按定义顺序组成的数组；
* `'flagentries'`：所有旗标变量的变量名和变量序号组成的数组按定义顺序组成的数组。

  > 假设 Flag.csv 如下定义：

  ```csv
  ; Flag.csv
  0,我是一个旗标
  1,我是另一个旗标
  ```

  > 那么 `'flagnames'`、`'flagkeys'` 和 `'flagentries'` 会返回如下内容：
  > * `'flagnames'`：`['我是一个旗标', '我是另一个旗标']`
  > * `'flagkeys'`：`[0, 1]`
  > * `'flagentries'`：`[['我是一个旗标', 0], ['我是另一个旗标', 1]]`

#### Item.csv 与 item 表

Item.csv 与 item 表相对应，也可称为道具表，用于定义和保存道具变量（表示持有多少个该种变量）和道具价格的信息。该表属于特定存档的一部分。

Item.csv 中的每行分为**三列**，第一列是 Number 类型的道具序号，第二列是 String 类型的道具名，第三列是 Number 类型的道具价格。道具序号和道具名都不能重复。

item 表的具体用法：

* `` `item:${道具名}` ``：道具名对应的道具的持有数量；
* `` `item:${道具序号}` ``：道具序号对应的道具的持有数量；
* `` `itemprice:${道具名}` ``：道具名对应的道具的价格；
* `` `itemprice:${道具序号}` ``：道具序号对应的道具的价格；
* `` `itemsales:${道具名}` ``：道具名对应的道具是否在售卖（Number 类型）；
* `` `itemsales:${道具序号}` ``：道具序号对应的道具是否在售卖（Number 类型）；
* `'item:bought'`：上次购买的道具序号；
* `'itemname:bought'`：上次购买的道具名；
* `` `itemname:${道具序号}` ``：道具序号对应的道具名；
* `'itemnames'`：所有道具的道具名按定义顺序组成的数组；
* `'itemkeys'`：所有道具的道具序号按定义顺序组成的数组；
* `'itementries'`：所有道具的道具名和道具序号组成的数组按定义顺序组成的数组。

#### Global.csv 与 global 表

Global.csv 与 global 表对应，该表也可称为全局变量表，用于定义和保存一些全局存档的变量。该表属于全局存档的一部分，不会被存读档行为改变，且会单独保存为 global.csv。具体细节可见 [#11 存档](./11-saves#通用公共存档文件-globalsav)。

global 表的具体用法：

* `` `global:${变量名}` ``：变量名对应的全局变量的值；
* `` `global:${变量序号}` ``：变量序号对应的全局变量的值；
* `` `globalname:${变量序号}` ``：变量序号对应的全局变量名；
* `'globalnames'`：所有全局变量的变量名按定义顺序组成的数组；
* `'globalkeys'`：所有全局变量的变量序号按定义顺序组成的数组；
* `'globalentries'`：所有全局变量的变量名和变量序号组成的数组按定义顺序组成的数组。

### 二维表：角色变量

二维表是指每个角色都有一个对应的数据表，每个角色的子表的基本结构为`变量名:变量取值`这样的变量对，操作变量时通过 `表名:${角色ID}:变量名`指定目标变量。二维表一般用于存储角色特定的变量。

#### Base.csv 与 base 和 maxbase 表

Base.csv 与 base 和 maxbase 两个表对应，也称为基础属性表。Base.csv 用于定义角色的基础属性变量，base 表用于保存角色当前的基础属性，maxbase 表用于保存角色对应的最大属性。必须使用 Base.csv 来定义这两个表的对象。base 表与 maxbase 表属于特定存档的一部分，会被保存到存档文件中。

> 引擎将 maxbase 设置为保护的表名，遇到 MaxBase.csv 时会在控制台显示警告而不会读取。

base 表的具体用法：

* `` `base:${角色ID}:${变量名}` ``：角色的变量名对应的基础属性值；
* `` `base:${角色ID}:${变量序号}` ``：角色的变量序号对应的基础属性值；
* `` `basename:${变量序号}` ``：变量序号对应的基础属性变量名；
* `'basenames'`：所有基础属性变量的变量名按定义顺序组成的数组；
* `'basekeys'`：所有基础属性变量的变量序号按定义顺序组成的数组；
* `'baseentries'`：所有基础属性变量的变量名和变量序号组成的数组按定义顺序组成的数组。

maxbase 表的具体用法：

* `` `maxbase:${变量名}` ``：角色的变量名对应的基础属性最大值；
* `` `maxbase:${变量序号}` ``：角色的变量序号对应的基础属性最大值；

在使用中，引擎会自动控制 base 表中的变量值，即小于0时重置为0，大于 `` `maxbase:${变量名}` `` 时重置为 `` `maxbase:${变量名}` ``。

#### Abl.csv 与 abl 表

Abl.csv 与 abl 表对应，也称为技能表，用于定义和保存技能变量。该表属于特定存档的一部分，会被保存到存档文件中。

talent 表的具体用法：

#### CFlag.csv 与 cflag 表

CFlag.csv 与 cflag 表对应，也称为角色旗标表，用于定义和保存角色旗标变量。该表属于特定存档的一部分，会被保存到存档文件中。

cflag 表的具体用法：

#### CStr.csv 与 cstr 表

CStr.csv 与 cstr 表对应，也称为角色字符串表，用于定义和保存角色字符串变量。该表属于特定存档的一部分，会被保存到存档文件中。

该表可以理解为字符串版本的 cflag 表，在添加或初始化角色时角色对应的子表中的所有变量会初始化为`''`而非0。

cstr 表的具体用法：

#### Equip.csv 与 equip 表

Equip.csv 与 equip 表对应，也称为装备表，用于定义和保存装备变量。该表属于特定存档的一部分，会被保存到存档文件中。

equip 表的具体用法：

* `` `equip:${角色ID}:${变量名}` ``：角色的变量名对应的装备变量值；

除以上内置的数据表外，EraElectron还支持自定义的数据表。开发者可以在csv文件夹下放置结构类似的变量数据表来增加自定义表。EraElectron引擎会自动识别、读取并以一维表方式初始化自定义表。如果想将其作为二维表使用，需要在配置文件（建议 \_fixed.json）中将表名添加到`system.extendedCharaTables`的数组中。

```json
{
  "system": {
    "extendedCharaTables": [
      "status"

  },
  "window": {
  }
}
```

# 相关 API

## era.get 和 era.set

> era.get 和 era.set 在 SDK 中和 [控制台对象 era](./07-debug#era-对象) 中的用法是相同的（只是控制台对象的函数的返回内容无法操作），如果阅读本节时遇到难以理解的内容可以在控制台中尝试一下。

![era.get](../imgs/57-era.get.png)

![era.set](../imgs/58-era.set.png)

主要用于读写游戏当前的存档数据的 API，可以看到参数结构非常类似。相同的参数 varName，String 类型，用于指定要操作的变量。era.set 有专属的第二参数 val，任意类型，用于指定要赋值给操作变量的新值。但若`val=undefined`，era.set 将和 era.get 一样只会返回要操作的变量的当前值，即 `era.get(varName)` 等价于 `era.set(varName, undefined)`。

varName 的格式与 [变量数据表](#变量数据表) 中提及的各类数据表的用法一致，例如 `era.get('flagnames')` 会返回 flag 表下所有的变量名，`era.set('cstr:0:称号','')` 会将 cstr 表中属于角色0的子表的、名为`称号`的变量设置为空字符串 `''`。除此之外，还有一些特殊用法（以下所有指称角色的变量A或B都是该角色的ID）：

### gamebase

`era.get('gamebase')` 会以对象形式返回 GameBase.csv 中定义的所有游戏基本数据，其中对象的属性为基本数据中的各类变量名。例如在启动本教程前两部分创建的游戏项目后， `era.get('gamebase')` 会返回以下内容：

```javascript
const result = {
    author: "你",
    info: "第一款Era游戏",
    year: "202X",
    title: "Example",
    gameCode: 114514,
    version: 1,
    allowVersion: 1
}
```

这个返回对象是只读的。

### version

`era.get('version')` 会返回当前操作的特定存档的版本号。特定存档的版本号的更多细节可见 [专属的特定存档](./11-saves#专属的特定存档-savesav)。

`era.set('version',val)` 在 val 是 Number 类型的时候会设置当前特定存档的版本号。

### chara

`era.get('chara')` 会返回所有有预设数据的角色的ID数组。例如csv文件夹下对0号到4号的角色设置了预设数据，`era.get('chara')` 会返回 `[0,1,2,3,4]`。这种用法是只读的。

_（PC 引擎 4.3.2、安卓引擎 1.2.4 及以上版本）_ ``` era.get(`chara:${id}`) ``` 会返回对象形式的、编号为 id 的角色的所有静态数据。

### callname

callname 是引擎为每个特定存档的创建的内置二维数据表，表示角色之间的称呼，其中的变量是 String 类型，内部由各个角色专属的一维表组成。

callname 表的具体用法：

* `` `callname:${A}:${B}` ``：角色A对角色B的称呼，角色数据表中以三列形式设定的callname变量会在A和B角色都添加后赋值给该变量；在读取时，引擎会首先返回该值，否则返回角色B的默认称呼，如果A或B还未添加则返回`'-'`；
* `` `callname:${A}:-1` ``：角色A的真实姓名，角色数据表中的name变量会在添加角色后赋值给该变量；
* `` `callname:${A}:-2` ``：旁白对角色A的称呼，角色数据表中以两列形式设定的callname变量会在添加角色后赋值给该变量；
* `` `callname:${A}` ``：角色A对所有角色的称呼的对象，其中的属性名为角色的ID或者是-1/-2，属性值则是对应的称呼字符串，这种用法是只读的。

callname 表支持读和写。

### relation

relation 是引擎为每个特定存档的创建的内置二维数据表，表示角色之间的好感度，其中的变量是 Number 类型，内部由各个角色专属的一维表组成。

relation 表的具体用法：

* `` `relation:${A}:${B}` ``：角色A对角色B的好感度，角色数据表中的relation变量会在A和B角色都添加后赋值给该变量，这种用法是可读写的；
* `` `callname:${A}` ``：角色A对所有角色的好感度的对象，其中的属性名为角色的ID，属性值则是对应的好感度数值，这种用法是只读的。

### love

love 是引擎为每个特定存档创建的内置一维数据表，表示角色对默认角色的爱慕值，其中的变量是 Number 类型。

love 表只支持 `` `love:${A}` `` 一种用法，表示角色A对默认角色的爱慕值。

love 表支持读和写。

### global

global 表除 Global.csv 定义的变量外，还有其他一些变量：

* `'global:code'`：返回当前全局存档所属的游戏标识，Number 类型；
* `'global:version'`：返回当前全局存档所属的游戏版本号，Number 类型，因为在读取游戏时会读取并转换全局存档所以会和 GameBase.csv 中定义的相同；
* `` `global:saves:${Index}` ``：返回序号为 Index 的特定存档的备注。关于存档文件的更多细节见 [#11 存档](./11-saves#专属的特定存档-savesav)。

global 表支持读和写。

### static

用于读取角色的预设数据，主要用法为：

* `` `static:${A}:name` ``：返回角色A预设数据中的姓名；
* `` `static:${A}:callname` ``：返回角色A预设数据中的默认称呼；
* `` `static:${A}:title` ``：返回角色A预设数据中的称号；
* `` `static${tableName}:${A}:${变量名或变量序号}` ``：返回角色A预设数据中属于数据表tableName的变量名或变量序号对应的变量的取值。

## （进阶）era.add

![era.add](../imgs/59-era.add.png)

与 era.get 和 era.set 相同，属于操作存档数据的API。如果将 era.set 理解为赋值号`=`，era.add 就是`+=`。

这个 API 的危险性在于并不对操作的变量作任何识别，如果是非数值类型的对象会产生意想不到的效果（大概率会得到一个`NaN`，JavaScript 中的特殊 Number 类型数值，表示非数）。

**在使用 era.add 时一定要注意实际操作的对象是什么类型！**

## era.logData 和 era.logStatic（控制台）

用于在控制台中输出数值的 API。

era.logData 会将所有存档数据输出为一个对象，属性为 data 和 global，分别对应专属存档数据和全局存档数据。data 属性中分为不同的表，global 属性中则是 global 表的变量值与 code、saves、version 等特殊属性。注意所有变量对应的属性名都是变量序号而非变量名，即 flag 表的0号变量（名为`我是一个旗标`，假设值为1）会显示为`{flag: {0: 1}}`。

```javascript
const result = {
  data: {},
  global: {}
}
```

era.logStatic 会将所有的静态数据输出为一个对象：

* 属性 static 中保存了游戏基础数据、\_Replace.csv 中定义的数据、所有变量数据表中变量名和变量序号的对应关系、以及所有角色的预设数据；
* 属性 names 中保存了所有变量数据表中变量序号和变量名的对应关系（注意和 static 中的映射方向相反）；
* 属性 resources 中保存了所有多媒体资源的注册名和相关信息的对应关系（详情见 [#16 多媒体资源处理](./16-resources)）。

```javascript
const result = {
  names: {},
  resources: {},
  static: {}
}
```

## 角色相关 API

### era.addCharacter

![era.addCharacter](../imgs/60-era.addCharacter.png)

在使用角色相关的数据表前，需要将相关角色添加到游戏中，这就是 era.addCharacter 的主要用途。如上图所示，era.addCharacter 接收可变参数 charaId，所有传入的参数都会成为 charaId 数组的一部分，其中的每个元素都会对应添加一个角色。

era.addCharacter 有两种用法，传入 Number 类型的参数（下文称为 id）时，该 API 会初始化 id 对应的角色，包括以下内容：

* 将角色id添加到已添加角色列表中；
* 为角色在所有非仅限调教使用的角色变量表中创建子表（此后对这些变量数据表中该角色的相关变量操作才会有效），并将子表中的所有变量初始化为角色数据表中的预设值或初始值（一般是0，cstr 表会是`''`）；
* 将角色的姓名和默认称呼赋值给 callname 表中角色对应的对象中的 -1 和 -2 两个属性；
* 将角色与其他已添加角色之间的称呼和好感度赋值给 callname 表和 relation 表中的相应变量；
* 根据角色当前的 base 表，给 maxbase 表中的相应变量赋值。

传入由两个 Number 数值组成的数组（下文称ids）时，该 API 会使用 ids\[1\] 对应的角色的角色数据表中的预设数值初始化角色 ids\[0\]。

era.addCharacter 的返回值是 Boolean 类型或其数组。只传入一个参数时返回单个 Boolean 类型的数值，表示该角色是否成功初始化；传入多个参数时，返回与参数数量相同长度的 Boolean 数组，按位对应角色的初始化成功情况。

### era.resetCharacter

![era.resetCharacter](../imgs/61-era.resetCharacter.png)

主要用于重置角色数据的 API，使用方法和 era.addCharacter 相同，会将对应角色的各项数据初始化为预设的数据或默认值。

### era.getAddedCharacters

![era.getAddedCharacters](../imgs/62-era.getAddedCharacters.png)

主要用于获取所有已添加的角色的ID，返回值是ID的数组。

### era.getAllCharacters

![era.getAllCharacters](../imgs/63-era.getAllCharacters.png)

主要用于获取所有有预设数据的角色ID，返回值与 `era.get('chara')` 相同。

## 调教相关 API

### era.beginTrain

![era.beginTrain](../imgs/64-era.beginTrain.png)

开始调教，创建所有仅限调教有效的变量数据表，初始化 tflag 表的所有变量值为0。必须调用该 API 后才能进入调教，不然会因为缺少必须的变量数据表而失败。

era.beginTrain 的参数与 era.addCharacterForTrain 完全相同，并在创建所有表后调用一次 era.addCharacterForTrain，初始化相应角色的的仅限调教有效的变量数据表。

变量数据表只会创建一次，也即反复调用 era.beginTrain 也不会重置变量数据表。

### era.addCharacterForTrain

![era.addCharacterForTrain](../imgs/65-era.addCharacterForTrain.png)

接受 Number 类型的可变参数 ids，传入的所有参数都会成为 ids 数组的一个元素，表示要添加到调教中的角色ID。对每个角色ID，会创建仅限调教有效的角色变量表下相应角色的子表，并初始化其中的变量为0。对每个角色的相关变量数据表的初始化只会执行一次，多次调用不会重置变量数据表。

### era.getCharactersInTrain

![era.getCharactersInTrain](../imgs/66-era.getCharactersInTrain.png)

返回目前添加到调教中的角色ID的数组。

### era.nextTurnInTrain

![era.nextTurnInTrain](../imgs/66.9-era.nextTurnInTrain.png)

将 delta 表结算到 param 表中，nowex 表结算到 ex 表中，并清空 source、delta 与 nowex 表。

### era.endTrain

![era.endTrain](../imgs/67-era.endTrain.png)

结束调教，将 gotjewel 表结算到 jewel 表中，并删除所有仅限调教有效的变量数据表，没有任何参数和返回值。

# （进阶）其他格式支持

除CSV之外，EraElectron引擎还支持使用可读性更强的其他数据格式定义静态数据文件，例如JSON和YAML。[例程](https://gitgud.io/umaera/game/ere-example) 中就同时展示了以三种不同的格式定义的静态数据文件，放在以格式名命名的文件夹中。

但注意 \_config.json 和 \_fixed.json **必须是JSON格式**。它们可以放到任意读者想使用的数据格式的静态数据文件夹下。

## JSON 格式

JSON（JavaScript Object Notation，JavaScript 对象表示法）是用于存储和交换数据的一种基于文本的格式，它易于人类阅读和计算机解析。因此，相对而言，JSON 易于学习和进行故障排除。虽然 JSON 源自于 JavaScript，但它已经发展成为一种非常强大的数据格式，可以简化不同平台和编程语言的数据交换。[^2]

[^2]: [什么是 JSON？ | Oracle 中国](https://www.oracle.com/cn/database/what-is-json/)

一个 JSON 文件可以被读取为一个 JavaScript 对象（对象或者对象数组），因此下文使用 JavaScript 对象的术语来描述 JSON 格式的静态数据文件的构成。

使用 JSON 格式最主要要注意的问题在于数据项的类型，`"1"`和`1`分别代表 String 类型和 Number 类型的数值，使用时必须加以区分（引擎对 CSV 格式有自动推断，但对 JSON 和 YAML 格式没有，因为在文件格式上它们已经带有类型定义了）。另外，JSON 格式**无法加注释**。

下面来分类介绍如何将静态数据文件从 CSV 格式转换为 JSON 格式。

### 游戏信息表

对于 GameBase 和 \_Replace 而言，其中的每行都定义了一个变量和变量的取值，在转换为 JSON 文件后需要以变量名为属性名，变量值为属性值，例如 [第一章创建的游戏项目](./01-basic#一切的开始新建项目) 的 GameBase.csv 可以转换为下面的 GameBase.json 文件：

```json
{
  "作者": "你",
  "追加信息": "第一款Era游戏",
  "发布时间": "202X",
  "游戏名称": "Example",
  "游戏标识": 114514,
  "版本": 1,
  "最低支持版本": 1
}
```

### 变量数据表

对于变量数据表而言，则需要以变量名为属性名，然后创建一个新对象并容纳变量序号为名为id的属性（书写顺序正好和CSV文件中的相反）。例如 [本章中的示例 Flag.csv](#flagcsv-与-flag-表)，可以被转换为下面的 Flag.json 文件：

```json
{
  "我是一个旗标": {
    "id": 0
  },
  "我是另一个旗标": {
    "id": 1
  }
}
```

item 表的定义文件则较为特殊，每个变量名对应的对象中还需容纳一个名为price的属性（值为该道具的价格），例如下面的两个等价的 Item.* 定义文件：

```csv
; Item.csv
0,我是一个道具,100
1,我是另一个道具,111
```

```json
{
  "我是一个道具": {
    "id": 0,
    "price": 100
  },
  "我是另一个道具": {
    "id": 1,
    "price": 111
  }
}
```

### 角色数据表

角色数据表和游戏信息表的转换类似，都是以变量名为属性名，变量值为属性值，但对变量数据表定义的变量则需要以表名（或表的变量名）为属性名整理成对象，例如下面两个等价的 Chara0000.* 定义文件：

```csv
; Chara0000.csv
角色编号,0
姓名,你
默认称呼,你
称呼,1,同学
基础属性,体力,1000
基础属性,精力,1000
基础属性,力量,100
```

```json
{
  "角色编号": 0,
  "姓名": "你",
  "默认称呼": "你",
  "称呼": {
    "1": "同学"
  },
  "基础属性": {
    "体力": 1000,
    "精力": 1000,
    "力量": 100
  }
}
```

可见在 JSON 格式下，角色数据表会变得规整很多，可读性也上升不少。

## YAML 格式

YAML 是 "YAML Ain't a Markup Language"（YAML 不是一种标记语言）的递归缩写。在开发的这种语言时，YAML 的意思其实是："Yet Another Markup Language"（仍是一种标记语言）。

YAML 的语法和其他高级语言类似，并且可以简单表达清单、散列表，标量等数据形态。它使用空白符号缩进和大量依赖外观的特色，特别适合用来表达或编辑数据结构、各种配置文件、倾印调试内容、文件大纲（例如：许多电子邮件标题格式和YAML非常接近）。

YAML 的配置文件后缀为 .yml，如：runoob.yml 。[^3]

[^3]: [YAML 入门教程 | 菜鸟教程](https://www.runoob.com/w3cnote/yaml-intro.html)

简单来说，相比 JSON 格式，YAML 可以不使用引号，以缩进代替大括号，因此可以非常方便地将 JSON 和 YAML 相互转换，例如 [这个在线工具](https://www.bejson.com/json/json2yaml/)。此外，YAML 格式可以有注释行，以`#`开头。

[本节前面的例子](#json-格式) 可以转换为以下的 YAML 文件：

```yaml
# GameBase.yml
作者: 你
追加信息: 第一款Era游戏
发布时间: 202X
游戏名称: Example
游戏标识: 114514
版本: 0001
最低支持版本: 0001
```

```yaml
# Flag.yml
我是一个旗标:
  id: 0
我是另一个旗标:
  id: 1
```

```yaml
# Item.yml
我是一个道具:
  id: 0
  price: 100
我是另一个道具:
  id: 1
  price: 111
```

```yaml
# Chara0000.yml
角色编号: 0
姓名: 你
默认称呼: 你
称呼:
  1: 同学
基础属性:
  体力: 1000
  精力: 1000
  力量: 100
```

## 相关游戏配置

当一个游戏项目中有多个格式的静态数据文件夹时，引擎会以 YAML、JSON、CSV 的优先级顺序选择一个文件夹读取。如果想指定静态数据的格式，可以使用 [游戏配置中的【静态数据文件格式】](./03-config#systemstatic静态数据文件格式无法在引擎中设置)，即修改 \_fixed.json：

```json
{
  "system": {
    "static": "csv"
  },
  "window": {
  }
}
```

> \_fixed.json 的其他部分不需要增删，在 `"system": {}` 内增加 `"static": "csv"` 即可。

`system.static` 的取值对应静态数据文件夹的名字，范围为 `"yml"|"json"|"csv"`。

引擎在没有指定 `system.static` 时读取 \_config.json 和 \_fixed.json 依然会按照优先级从相应静态数据文件夹中读取，因此 \_fixed.json 需要同时放置在优先级最高的文件夹中和 `system.static` 指定的文件夹中 ~~所以请尽量避免这么做orz~~。

_PC引擎3.5.0及以上版本_

在加载游戏后，可以使用引擎在相同游戏文件夹下生成其他格式的静态文件：

![格式转换](../imgs/59-1%20格式转换.png)

格式名的后缀表示生成文件的风格，点击带有（可读）后缀的功能项时会在生成角色的静态文件时将变量序号转换为对应表的变量名，带有（兼容）后缀的则会直接以变量序号生成。

该功能不会覆盖当前读取的静态数据文件，也即在读取 YAML 格式的静态数据文件进入游戏的情况下无法通过此功能生成 YAML 格式的静态数据文件。

# 小结

本章介绍了静态数据文件类型与相关用法，包括用于定义游戏信息、变量数据和角色数据的三类静态数据文件，era.get 和 era.set 等相关 API 及特殊用法，以及作为进阶内容的可定义静态数据的其他文件格式。

JSON 格式和 YAML 格式的好处是可以在给出静态数据基本定义的基础上扩展额外信息，比如指定变量的类型和在代码中直接使用的变量名等，这一点在 [开发套件](./18-tools#开发套件) 的生成和使用中尤为重要。
