---
title: '#7 调试'
---

在构建交互逻辑之后，这个从寥寥几行代码成长起来的程序就可以称之为游戏了。随着交互逻辑在输入和输出两端的逐渐扩展，游戏会变得复杂，自然会出现显示内容和预期不符的情况。这或者是因为数值的计算错误，或者是对显示内容的设置错误。为找出错误并加以修正，我们需要对游戏进行调试。

EraElectron引擎对调试的支持主要分为两方面：首先，引擎自带一个控制台，可以通过输入指令（单行或多行javascript代码）查看变量、查看控制输出内容的对象等；其次，可以通过控制台对象和 SDK 启用调试模式，并通过 SDK 中的 era.logger 系 API 输出计算内容来检查结果的正确性。

# 控制台

## 打开控制台

EraElectron引擎的控制台可以通过菜单栏中的【调试】-【控制台】进入。

第一次打开控制台时，控制台会出现在引擎的界面中，挤占游戏画面的一部分空间，如下图所示：

![第一次打开控制台](../imgs/34-控制台.png)

此时需要点击控制台右上角叉号旁边的竖状省略号调出控制台菜单，并在其中的第一行停靠侧选项中选择最左边的图标，然后控制台就会呈独立窗口显示，不再挤占游戏画面的空间了：

![第一次打开控制台](../imgs/35-停靠侧.png)

第一次打开的控制台显示语言一般为英语，此时控制台顶部会有提示问是否切换为中文（Switch to Chinese），点击切换后就会切换为中文界面了。

打开控制台后建议在其中随意输入一些数字并按回车，控制台可能会提示这是危险行为，需要在控制台中手动输入一些文字才能解锁，此时按照控制台的提示输入文字并回车，之后就能正常使用控制台的所有功能了。

## 控制台对象 era 和 ere

EraElectron引擎的控制台功能主要通过两个对象提供：era 和 ere。读者可以不经任何前置操作地在控制台中输入并使用它们：

![控制台对象](../imgs/36-控制台对象.png)

上图中通过在控制台直接输入这两个对象查看到了对象的内容，可以看到它们分别由一些函数属性组成。这些函数提供了控制台调试用的主要功能。其中 era.* 主要面向游戏数据的调试需求，ere.* 则主要面向游戏界面的调试需求。

### era 对象

era 对象主要提供面向游戏数据的调试需求，由7个函数组成。

> EraElectron引擎是基于Electron的，其负责显示的模块与负责读取游戏脚本和数据的模块是分离的，所以面向游戏数据的调试需求的 era 对象的函数全都需要进行跨模块通信，也就是异步调用，因此 era.* 的直接返回值全都是 `undefined`，而其真正的返回值（跨模块通信的结果）则会紧跟 `undefined` 出现在下一行。<br>
> **永远不要在控制台中同时使用两个以上的 era 对象的函数！**

era.* 可以分为以下四类：

#### era.add、era.get 和 era.set：存档数据读写

这三个函数可以用于读写游戏当前的存档数据，使用方式和 SDK 中它们三个的同名函数相同，具体细节见 [#9 静态数据文件](./09-static#eraget-和-eraset)。

> 当然，读者也可以用它来修改游戏。<br>
> 所以看到这里的读者请不要再用CE去修改游戏了QAQ

#### era.logData 和 era.logStatic：游戏数据查看

这两个函数可以输出游戏当前的存档数据和静态数据，具体细节见 [#9 静态数据文件](./09-static#eralogdata-和-eralogstatic控制台)。

#### era.toggleDebug

era.toggleDebug 用于控制调试模式的开关，并返回当前是否处于调试模式。

![era.toggleDebug](../imgs/37-era.toggleDebug.png)

上图在调用 era.toggleDebug 之后出现的 `true` 表明此时已经将游戏的调试模式打开了。再次运行后会出现 `false`，表明调试模式已被关闭。

#### era.cleanSave

era.cleanSave 可以用于删除存档。其接受一个 Number 类型的参数，用于指定特定存档栏位号。

### ere 对象

ere 对象目前只有一个函数：ere.showLines。

![ere.showLines](../imgs/38-ere.showLines.png)

ere.showLines 在调用后会输出当前界面上每个显示行的控制对象（在 era.print 系 API 调用的过程中产生）。开发者可以点击这个输出结果，并展开 `[[Target]]` 来检查控制对象来判断预期的显示内容是否成功被输出到显示界面了。

> 这里涉及到EraElectron引擎的基本工作原理，在游戏脚本中调用 API 控制界面进行显示时，API 会将相关的显示内容和设置参数生成一个控制对象发给引擎的显示界面，显示界面根据控制对象的内容决定显示的内容。<br>
> 之前介绍的编程意义上的行和实际显示中的行的根本不同也就源于此处，编程意义上的一行是指这样的控制对象控制的一行。因为每个控制对象都是与 API 调用一一对应的，所以理解为一次 API 调用就会产生编程意义上的一行。

在【自动压缩空行】等设置下，游戏引擎会根据控制对象的内容决定是否在界面上显示。例如下面这样的 `#/main.js` 内容：
```javascript
const era = require('#/era-electron');

module.exports = async () => {
  era.print('下面输出了两个空行，但只会显示一个。');
  era.println();
  era.println();
  await era.printAndWait('上面输出了两个空行，但只会显示一个。');
};
```

在开启【自动压缩空行】后重新读取游戏，界面上显示：

![压缩空行](../imgs/39-压缩空行.png)

此时在控制台中通过 ere.showLines 检查当前每个显示行的控制对象：

![控制对象](../imgs/40-压缩空行的控制对象.png)

可以看到一次 era.print、两次 era.println 和一次 era.printAndWait 其实都产生了一个控制对象。但是因为【自动压缩空行】选项的设置，第一个 era.println 对应的控制对象（`1: {_s: Array(2), type: 8, show: true}`）的 show 属性设置为 `true`，第二个的 show 属性则为 `false`，此时引擎判断 show 属性为 `false` 的控制对象不需要显示在界面反映，因此界面上只会显示一个空行。

在启用调试模式的情况下，控制对象中的 \_s 属性会显示生成这个控制对象的调用栈（一种展示函数相互调用关系的数据结构）信息，开发者可以通过该属性查看到控制对象具体是哪个脚本文件中的哪次 API 调用产生的。

# 调试模式

引擎可以通过控制台对象 era 的函数 era.toggleDebug，或者 SDK 的 API era.toggleDebug 进入调试模式。在调试模式下，引擎会输出更多内容。

> 进阶：引擎可以从命令行启动，然后在调试模式下读取游戏脚本时会显示读取到的脚本文件列表。当然如果不启用调试模式也可以通过【调试】-【游戏文件列表】在命令行手动输出。<br>
> 从命令行启动的方法是在命令提示符或终端上进入到游戏引擎所在的文件夹，输入大写字母ERA，按Tab键自动补全后回车即可。
> 这个方法在游戏文件变得更复杂后还可以用于检查循环依赖（会导致模块导入导出失效）。

本节主要介绍 SDK 中与调试模式相关的 API。

## era.toggleDebug 和 era.isDebug

era.toggleDebug 和控制台对象的函数功能相同，但可以用于游戏脚本中。这个 API 是个同步函数，返回 Boolean 类型的返回值，表示之后是否处于调试模式。

era.isDebug 是辅助 era.toggleDebug 使用的 API，返回值的意义和 era.toggleDebug 相同，但不会导致调试模式的进出。

## era.logger 系 API

era.logger 是 SDK 的一个对象属性，主要用于输出日志和显示提醒信息，其中有4个 API：

### era.logger.info

接受一个 msg 参数，可以是任何内容，然后会在控制台中输出它，并附上调用者及文件信息。

### era.logger.error

接受两个参数，msg 为必选，是要输出的主要内容；stack 为可选，是当前的调用栈信息。

与 era.logger.info 不同的是，era.logger.error 会在引擎界面中触发一个右上角的 error 类型的浮动提醒信息，标题为「脚本错误」，内容则是参数 msg。如果没有调用栈信息，会自动填充当前调用栈。

一般有如下两种用法：
```javascript
era.logger.error("这是一条报错信息");

// Error 是 JavaScript 内置的异常信息类
// try ... catch (e) ... 中的 e 就是 Error 类的实例
era.logger.error("这是一条带调用栈信息的报错信息", new Error().stack);
```

### era.logger.debug

接受参数 info，要输出的主要内容。如果在调试模式下，在控制台中输出它，并附上调用者及文件信息。

era.logger.debug 是调试的主要承担者，注意它**只会在调试模式生效**。开发者可以在开发过程中随意使用它输出游戏脚本运行过程中的各种数据和信息，而在非调试模式下 era.logger.debug 因为不生效所以不会干扰玩家的游玩。

### era.logger.warn

_PC引擎 4.2.2_

接受两个参数，msg 为必选，是要输出的主要内容；stack 为可选，是当前的调用栈信息。

用法与 era.logger.error 相似，会在控制台打印调用栈信息，如果没有传入调用栈则自动生成。不同的是，不会在界面右上角弹窗。

### era.logger.assert

断言，接收两个参数 checkVal 和 aimVal，然后检查它们是否全等。如果不全等，在引擎中显示浮动提醒信息并在控制台中输出调用栈信息。开发者可以用来检查数值计算的结果是否符合自己的预期，主要用在测试中：例如给定一段逻辑和输入，然后检查该逻辑最后的输出值是否符合预期。

era.logger.assert 在非调试模式下仍然生效，不过仅在两个参数不全等时触发，因此在游戏脚本按预期运行的情况下是不会干扰正常游玩的。不过还是建议在测试结束后将断言删除。
